# 局域网层（v0.5 · M3）

> 这一期让**四个人各自开一条船，在同一个大西洋上待上十分钟，两边的世界不会越走越远**。
> 对应 `docs/13-v0.5开发计划.md` 的 M3 卡片；状态边界在 `docs/14`；
> 世界分块在 `docs/15`。它是 v0.5 里风险最高的一期（±50%），所以排在任何大内容之前。

---

## 1. 一局里谁说了算

**星型**：一台房主，2–4 个客户端都只跟房主说话（客户端之间不直接连）。

| 层 | 谁写 | 上网吗 | 怎么传 |
|---|---|---|---|
| 世界（时钟 / 风 / 剧情 / 日志 / 已发现的图 / AI 船） | **房主** | 是 | 房主每 0.5 秒广播一次 WorldState；客户端**只读覆盖** |
| 自己那条船（位姿 / 帆 / 损伤 / 名册 / 登陆队） | **拥有者** | 摘要上网 | 拥有者 20Hz 广播摘要，房主转发给其他人 |
| 40 人逐人状态、帆的实时攻角、舵的积分项 | 拥有者 | **永不过网** | —— |

**最大的好处**：每台机器永远只细化**一艘**船。四艘船在同一个世界里，
单机负载和 v0.1 一模一样 —— 所以不需要把每船 40 人缩编，
也不需要"进了别人的船就降级"。

**必然推论（已经写进 UI 规矩）**：别人的船只有外观与汇总数值。
`sea_debug.gd` 给别人的船各挂一个 `ShipRenderer`，但**一个船员点都没有** ——
那不是省事，是因为那边根本没有逐人模拟。

## 2. 一个船位在哪台机器上是什么

`scripts/fleet.gd`：

| kind | 谁在跑 | 有什么 | 在画面上的样子 |
|---|---|---|---|
| `local` | 本机 | 气动积分 + 40 人名册 + 登陆队（在 `Voyage` 里） | 真正的船，可以滚轮沉进船舱 |
| `ai` | 房主 | 一个 9 键摘要，朝目标走（`abstract_ship.gd`） | 外观 + 「名字　在干什么　船体%」 |
| `remote` | 别人 | 20Hz 摘要，**100ms 插值** | 同上（没有逐人细节） |

**摘要只有这九个键**：`id / name / pos / heading / sail_level / anchored /
hull_pct / crew_count / action`。`tests/test_fleet.gd` 把这条钉成了断言：
多一个键就报错 —— 想给别人的船多发点东西的人，会先撞到这张白名单上。

### 2.1 升降级

```
attach_player(id, peer)   抽象 → 细化：接手方拿到那份摘要（船体% / 人数 / 位置 / 艏向），
                          名册按同一份数据集重新生成
detach_player(id, target) 细化 → 抽象：丢掉逐人细节，只留汇总；**船不消失**，
                          照着船队这一程的目的地继续走
```

掉线那条特意留了 `target` 参数：房主知道船队往哪儿去，就把坐标传进去，
没人开的那条船会自己跟上去；不传就照当前艏向继续 —— 总之不会在海上停下来。
（"掉线 = 船停在原地"是最容易写出来的错。）

## 3. 快进与网络是两条钟

这是这一期最容易写错的地方：

- **游戏时间**可以被 `.` 键快进 ×36（M2 加的档位）；
- **网络**不行：20Hz 是真实世界的 20Hz，插值的 100ms 也是真实世界的 100ms。

所以 `Voyage` 有两个入口：

```gdscript
voyage.tick(dt)        # 游戏时间：气动、船员、AI 船、剧情
voyage.tick_real(dt)   # 真实时间：网络收发、远端船插值、界面计时
```

画面里两个都调（一个跟 `SIM_DT` 走固定步长，一个跟帧走）——
`sea_debug.gd` 的 `_process` 就是这两行。

如果偷懒把两者合成一个，就会出现："×36 的时候别人的船每包跳 40 米"
（0.5 秒真实时间 × 36 = 18 秒游戏时间 × 2.2 m/s）——
这不是猜的，是这一期真踩到的坑。

## 4. 消息清单（唯一的真源在 `scripts/net/net_protocol.gd`）

| 消息 | 方向 | 说明 |
|---|---|---|
| `hello` | 客户端 → 房主 | 我是谁、协议版本 |
| `welcome` | 房主 → 客户端 | 你开哪条船 + 世界快照 + 船队快照 + 海域路径 |
| `full` | 房主 → 客户端 | 船位满了 / 协议版本不同（好好说一声，不静默失败） |
| `ship` | 拥有者 → 房主 → 其他人 | 20Hz 的船位摘要（**不可靠**通道：丢一包不过晚 50ms 画一次） |
| `world` | 房主 → 全部 | 每 0.5 秒一次的世界状态（**可靠**通道） |
| `input` | 客户端 → 房主 | 会影响"世界"的动作（目前只有"记一条决定"） |
| `ping` / `pong` | 双向 | 心跳；房主 3 秒收不到就把那条船转 AI |
| `bye` | 谁 → 房主 | 我要走了（正常退出；掉线靠心跳超时） |

**协议版本不符直接拒绝**，和存档一个口径（`docs/14` §4.2）：v0.5 内不承诺兼容。

## 5. 怎么验证

```powershell
# 两个无头进程，真 ENet，真回环地址，10 分钟游戏时间（×36 → 约 17 秒真实时间）
& $g --headless --path . --script res://tests/test_net_loopback.gd

# 船队与升降级（不联网的那一半）
& $g --headless --path . --script res://tests/test_fleet.gd
```

`test_net_loopback` 干的事：房主开房 → 拉起**一个客户端进程** → 跑到游戏时间
300 秒时**再拉起第二个客户端进程**（中途加入，接手一条 AI 船）→ 跑到 600 秒
→ 两个客户端各交一份 JSON 报告 → 房主逐项对账：

| 对账项 | 口径 | 实测 |
|---|---|---|
| 时钟 | 差 < 3 秒游戏时间 | ≈ 0.1 秒 |
| 四条船的位姿 | 两边看到的差 ≤ **一个船身**（20 米） | 11–14 米（= 100ms 插值延迟） |
| 客户端自己那条船 | 房主看到的 vs 它自己算的 | ≈ 13 米 |
| 船体% | 差 < 2% | 0.000 |
| 剧情旗标 / 演到第几幕 | 完全一致 | 一致 |
| 中途加入 | 第三人接手一条 AI 船，其他人看得见 | 通过 |
| 掉线 | 那条船转 AI、继续走、房主的存档还能存能读 | 通过（走了 179 / 190 米） |

为什么插值误差是 11–14 米而不是 0：远端船按 **100ms 延迟**插值（不外推），
快进 ×36 下 100ms 就是 3.6 秒游戏时间 —— 一条 2.2 m/s 的船正好走 8 米左右，
再加上 20Hz 采样间隔与两端时钟的零点几秒差，就是十来米。
**这正是一个船身的量级，也正是验收标准写"≤ 一个船身"的原因。**

## 6. 房间界面

### 6.1 客户端那条路漏了两步（2026-10-02 第一次真人两台机器试出来的）

用户按"解压两份、一份开房一份加入"试了一把，报了三件事：**看不见房主**、
**加入的人没有 UI**、**没有 id 标识**（房主那边一切正常）。三件事其实是同一条路上的两个漏步 ——
都是**只走了单机那条路**才会漏的：

1. **`_on_welcome()` 没把航行界面打开**：它只把房间界面收起来（`_room.visible = false`），
   而 HUD 层与面板层在开局是隐藏的（等玩家选完"单机出海"才由 `_begin_voyage()` 打开）。
   于是客户端进游戏后**没有 HUD、没有消息条、按 Tab/C/K 也没反应** ——
   唯一还能用的左键（点目标点）是画在海面上的，所以"除了移动都不能做"。
   修法：客户端那条路也走 `_begin_voyage(false)`。
2. **"别人的船"渲染器没跟着换名单**：`_fleet_views` 是**开局**按当时的船队建的
   （那时本机默认开特立尼达），而客户端开哪条船是**房主分的** —— 分到手之后
   `local_id` 变了，"别人那几条"整个换了名字。不重排的后果：
   **房主那条船没有渲染器（看不见）**，而自己那条船反而被画两遍。
   修法：`_on_welcome()` 里调 `_rebuild_fleet_views()`。

**为什么之前没抓到**：`test_net_loopback` 跑的是**纯 `Voyage`**（两个无头进程，没有场景层），
它验的是状态收敛；而这两个 bug 都在**场景接线**里。现在 `test_save` 的"场景接线"那一节
模拟了一次"客户端加入"（`_on_welcome("san_antonio", …)`）并断言：HUD 与面板层可见、
房间界面收起、本机开的是房主分的那条船、**每条"别人的船"都有渲染器**、
且自己那条**不在**"别人的船"名单里（6 条）。

> 顺带记两条实测结论：`test_net_loopback` 的**状态层**没问题（25 项全绿、四条船位姿
> 差 ≤ 一个船身）；问题全在**场景层**没接线。以后加联机功能，场景级断言要和进程级一起加。

`scripts/room_panel.gd`：开场第一屏，三条路径 + 四个船位的占用情况。

```
1 单机出海      一个人 + 三条 AI（和联机同一条代码路径）
2 开房间        本机当房主，别人用 IP 连进来（默认端口 47777）
3 加入房间      输 IP 回车；中途加入会接手一条 AI 船
```

**砍单预案已执行**：没做 UDP 局域网自动发现，只留手输 IP（`docs/13` M3 卡片的
砍单预案第一条就是这个）。换 IP 只要按 `I` 编辑、回车连接。

## 7. 这一期踩到的坑（都写进 `AGENTS.md` 了）

| 坑 | 症状 | 对策 |
|---|---|---|
| `SceneTree` 的 root 在 `_initialize()` 里还没进树 | `multiplayer` 是 `null`，一开房就 "Invalid access on a null instance" | 网络在第一帧之后建（`_process` 里 boot） |
| ENet 不显式给通道数 | "Unable to send packet on channel 0, max channels: 0" | `create_server(port, n, CHANNELS)`，客户端也一样 |
| 只设了 `link.voyage`，没设 `voyage.link` | 客户端一切正常、房主一个包都不发（表现是"别人的船一直停在原地"） | `NetLink.attach()` 双向接上，别只接一头 |
| AI 船的摘要跟着 WORLD 走（0.5 秒一次） | ×36 时 AI 船每包跳 40 米 | AI 船和玩家船一样 20Hz 单独发摘要 |
| 把游戏时间和真实时间混用 | 快进时插值、心跳、发包节奏全乱 | `tick()` / `tick_real()` 分开 |
