## 1. 简化三原则（未变）

1. **一艘船，一片海，一个故事。** 不做船队、不做世界地图、不做多结局。
2. **只模拟玩家看得见的东西。** 看不见的舱室活动，用一条延迟消息概括。
3. **每个系统只做"能撑起一条体验链"的最小版本。**

## 3. 垂直切片的 6 根支柱

原计划 5 根，因为第 5 条决策（指挥官不直接操船），新增**支柱 3：指挥链路**。

### 支柱 1：结构化、多层的单桅帆船

4 层格子图，层间由梯子/舱口连通。

| 层 | 内容 | 用途 |
|---|---|---|
| L3 桅顶瞭望台 | 一小块平台 | 瞭望、发现岛屿 |
| L2 主甲板 | 舵、桅杆底座、绞盘、舱口、炮位占位 | 操船（**用格子**） |
| L1 下层甲板 | 船员铺位、厨房、船长室、医务角 | 船员生活（**用房间**） |
| L0 货舱 | 货物、淡水桶、压舱石 | 资源存放（**用房间**） |

**你已确认**：主甲板用格子，舱内用房间。这正好对上混合方案——
甲板要精确（走位、调帆位置），舱内只要"在哪个房间"。

**数据驱动**：船 = `ship.json` + 一组 SVG 部件，改数据不改代码。

### 支柱 2：风与帆（气动模拟）

```
真风 TWS/TWD → 视风 = 真风 − 船速矢量
            → 帆的攻角 α → Cl(α) / Cd(α)
            → 升力 L ⊥ 视风，阻力 D ∥ 视风
            → 推力 vs 船体阻力 + 龙骨诱导阻力
            → 侧向力 → 侧滑 + 横倾
            → 积分出 位置 / 艏向 / 速度 / 横倾
```

**验收硬指标**：① 真风角 35–40° 内无法推进 ② 横风最快 ③ 顺风明显慢 ④ 最佳抢风角 40–45°。

### 支柱 3：指挥链路（新增 · 你最重要的改动）

你明确了：**玩家不能直接下舵、不能直接调帆，只能选目标点，由船员执行**。
这不只是操作方式的改变，它是整个设计的粘合剂——因为它让**船员技能直接等于船的机动性**。

```
玩家的动作                          系统内部
──────────────────────────────────────────────────────────
点击目标点 / 选航向指令   ──→  换算成"目标航向"
选择帆的档位                      （全帆 / 缩帆 / 收帆 / 抛锚）
                                    ↓
                        航海官评估：目标航向 vs 当前航向 vs 风向
                                    ↓
                        选择航法：保持 / 转向 / 抢风换舷 / 顺风换舷
                                    ↓
                        下达调帆指令（主帆角 / 前帆角 / 舵角）
                                    ↓
                        船员执行（耗时 = f(技能, 人数, 疲劳)）
                          · 速度 → 调帆快慢
                          · 精度 → 最终离最优攻角差多少
                                    ↓
                        帆的实际收放角 → 气动模型 → 船体运动
```

**为什么这条链子值得单独当一根支柱**：

- 玩家在**目标与风险**上做决策，而不是在"按哪个键收帆"上做操作。这才配得上"船长"的视角。
- **船员疲劳 → 换舷变慢 → 在暗礁前来不及转向 → 撞上。** 一个完全由系统自己长出来的事故，不需要脚本。
- 帆态面板成为必需：玩家必须能看懂"船慢"到底是**风不对**还是**船员没调好**。

**玩家能下达的指令（切片的全部）**：

| 指令 | 说明 |
|---|---|
| 设定目标点 | 在海图上点一个点，领航员负责走 |
| 帆档位 | 全帆 / 缩帆 / 收帆 |
| 抛锚 / 起锚 | 靠岸、避风用 |
| 人员安排 | 改工作优先级、抽调人手（会直接影响操船速度） |

### 支柱 4：类环世界船员（12 → 40 人）

你要求**符合历史**，12 名关键船员先落地，逐步扩到 40 人。

**12 名关键船员（16 世纪伊比利亚远洋船的真实编制）**：

| 3 | 舵手 | Timonel | 掌舵 |

| 5 | 木匠 | Carpintero | 修船体 |

| 7 | 桶匠 | Tonelero | 制桶修桶——**淡水与食物的载体，历史上极关键** |

### 支柱 5：摄像机 + 帆态观察面板

**主视角：纯正交俯视**（你已确认），跟随船或船长。三种状态：

| 状态 | 触发 | 摄像机 | 玩家做什么 | 船 |
|---|---|---|---|---|
| A 甲板 | 默认 | 锁定船，正交俯视 | 选目标点、看帆态 | 船员操控 |
| B 舱内 | 滚轮向下穿过甲板 | 进入分层视图 | 看船员、调优先级 | 同上 |
| C 离船 | 船长带船员登陆 | 跟随船长 | 探索、交涉 | **交给大副自动运行** |

**帆态观察面板**（对应你说的"三视图或矢量 3D 图"）——三个区域：

| 区域 | 内容 | 回答什么问题 |
|---|---|---|
| A 俯视矢量图 | 真风矢量、视风矢量、船速矢量、帆弦线、升力/阻力、推力↔侧力分解 | "风从哪来、帆吃上力了吗" |
| B 侧视剪影 | 横倾角、帆的拱度、桅杆倾斜 | "船是不是压得太狠了" |
| C 数值条 | 视风角、攻角、升阻比 L/D、推力、侧力、横倾、**失速警告** | "为什么慢" |

**还有一个可选加项**：正交三视图小窗（俯视 / 侧视 / 艉视），用来看船体损伤和帆面形状。
这是"锦上添花"，不做也不影响支柱成立——**需要你决定要不要**（见第 10 节问题 4）。

### 支柱 6：测试海域 + 登陆 + 三幕剧情

| 要素 | 内容 |
|---|---|
| 地形 | 出发港、**1 座可登陆的岛**、1 处暗礁、1 条洋流带 |
| 岛 | 登陆滩头 → 内陆遗迹 → 淡水溪流 → 部落村落（接触事件） |
| 登陆 | 玩家**带船员登岛**：选人 → 离船 → 摄像机跟随 → 船上交给大副 |
| 风 | 全局风向随时间缓变 + 岛屿背风区风速降低 |
| 事件 | 5 个：瞭望员报告 / 风向突变 / 船员伤病 / 发现遗迹 / 部落接触 |
| 三幕 | 出港学操帆 → 发现岛并抉择是否登陆 → 返航结算 |

**验收**：陌生人 15 分钟走完全程，事后能复述"我在哪做了什么决定、结果怎样"。

## 4. 系统骨架

```
   ┌──────────────────────────────────────────────┐
   │ 玩家：选目标点 / 选帆档 / 调人员               │
   └───────────────────┬──────────────────────────┘
                       ▼
   ┌──────────────────────────────────────────────┐

   └───────────────────┬──────────────────────────┘
                       ▼
   ┌──────────────────────────────────────────────┐
   │ 船员执行：调帆速度 f(技能,人数,疲劳)           │
   │           调帆精度 → 实际攻角                  │
   └───────────────────┬──────────────────────────┘
                       ▼
   ┌──────────────┐   实际帆角
   │ 风场 Wind     │──┐
   └──────────────┘  ▼
                  ┌──────────────┐
                  │ 帆之气动 Sails│ 主帆 + 前帆
                  └──────┬───────┘
                         ▼
                  ┌──────────────┐
                  │ 船体动力学 Hull│ 阻力/龙骨/舵/横倾
                  └──────┬───────┘
                         ▼
                  ┌──────────────┐
                  │ Ship 位置/艏向│
                  └───┬──────┬───┘
                      ▼      ▼
              ┌──────────┐ ┌──────────┐
              │ 分层船体  │ │ 船员需求  │
              │ 4 层      │ │ 状态机    │

                 ┌────────────────┐
                 │ 摄像机 + 帆态面板│ A 甲板 / B 舱内 / C 离船
```

**唯一的数据流原则**：玩家 → 船员 → 帆 → 船 → 表现。
**任何系统都不允许直接改船的速度或位置**，包括剧情事件和调试工具。
这是气动模拟不被污染的唯一保障。

## 5. 美术管线：SVG 部件拼装（你已确认）

船用**手绘 SVG 部件**拼装，不用位图，不用 AI 生成位图——因为矢量图能随意缩放，
正交摄像机拉近拉远都不糊，而且**换一个破损版的帆就是换一个 SVG 文件**，
损伤可视化变得几乎免费。

```
assets/ship/parts/
  hull/    船体轮廓、船壳板、龙骨剪影
  deck/    甲板铺板、舷墙、栏杆、舱口、梯子
  rig/     桅杆、帆桁、索具、缆绳
  sails/   主帆、前帆、收帆状态、破损状态
  fittings/ 舵柄、绞盘、锚、炮、铃、舷灯
```

每个部件是一个独立 SVG，带**锚点**和**拼接层序**，Godot 在运行时读 `ship.json`
把部件按坐标拼成完整的船。详细清单见 `03-单桅帆船SVG部件清单.md`。

**拼装示意**：
```
   船壳轮廓  →  甲板铺板  →  舷墙/栏杆  →  舱口/梯子
        →  桅杆  →  帆桁  →  主帆  →  前帆  →  索具  →  舵/绞盘/锚
```

## 10. 两处规格冲突（**已解决**）

> **结论**：冲突 1 选 **B**（60 吨单桅拉丁帆）；冲突 2 接受**双层模型**。
> 下面的原始分析保留，作为日后再遇到类似取舍时的判断依据。

### 冲突 1：25 吨 / 15 米的船，装不下 40 个人

这不只是"住得挤"的问题，是**远洋补给装不下**：

| 项目 | 计算 | 重量 |
|---|---|---|
| 饮用水 | 40 人 × 3.5 L/天 × 60 天 | 约 8.4 吨 |
| 食物 | 40 人 × 1 kg/天 × 60 天 | 约 2.4 吨 |
| 弹药、备件、帆布、备用桅杆 | 估算 | 约 3–4 吨 |
| **合计载重需求** | | **约 14 吨** |

25 吨排水量的船，载重能力（deadweight）大概只有 8–12 吨——**装不下**。
历史上 25 吨级的船，船员就是 8–15 人。

而你设定的是**环球航行**，麦哲伦舰队里最小的 Santiago 也有 75 吨。

**三个选项**：

| 选项 | 船 | 船员 | 历史合理性 |
|---|---|---|---|
| A | 25 吨 / 15 米 | 封顶 12–15 人，放弃扩到 40 | 合理，但"40 人"作废 |
| B | **约 60 吨 / 20 米，单桅拉丁帆** | 25–30 人 | 合理（真实的 caravela latina 探索船） |
| **C（推荐）** | **约 90–100 吨 / 23 米** | **40–45 人** | 合理，对标麦哲伦的 Victoria（85 吨）/ Concepción（90 吨） |

**我推荐 C**：它同时满足你的"40 人"和"符合历史"，唯一的代价是桅杆——
真实的 90 吨船是 3 桅，但我们**先做 1 根桅杆**，Day 8 之后再往上加，
数据结构和 SVG 拼装都预留了加桅的能力。

### 冲突 2：40 人全员跑完整模拟，性能与工作量都超预算

`ship.json` 的 4 层里，40 个人同时寻路 + 需求循环，在 7 天内做不完也调不好。

**建议**：**双层模型**
- 12 名关键船员：完整模拟（需求、心情、关系、技能影响操船）
- 28 名普通船员：简化模拟（只有"岗位 + 一个工作状态"，在甲板上表现为小人）

这也正是原设定第二十一节"其他船只抽象模拟"的思路，只是用在船员身上。

### 规格 B 的连带影响（我重新算了一遍补给，结论有修正）

我之前说"B 只能带 25–30 人"，**这个说法是错的，我修正一下**：

60 吨木质帆船的载重能力（deadweight）约为 **24–30 吨**。
40 人 × 60 天的消耗是：淡水 8.4 t + 食物 2.4 t + 桶重约 2 t + 弹药备件 3 t ≈ **16 吨**——
**装得下**。所以规格 B 支持你原本要的 40 人，不用退回 A，也不用升到 C。

而且这里有个意外的好处：历史上 60 吨级船的常见编制是 20–30 人，
**40 人属于超编**。这正好给游戏提供了一个天然的资源压力来源——
人多了，淡水就不够，于是"要不要少带人""要不要在岛上补水"变成了真实的抉择。
这比凭空设计一套资源压力系统要自然得多。

具体影响：

- **`hull_outline.svg` 按 20 米船体绘制**（不是原来说的 15 米），艏艉更修长，艉楼更高。
- **船员目标维持 12 关键 → 40 总**，其中 28 人用简化模型。
- **`ship.json` 仍是 4 层**，但货舱面积变大，淡水桶和货桶会明显变多（这本身是超编压力的可视化）。
