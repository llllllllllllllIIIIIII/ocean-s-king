# 世界分块与海图（v0.5 · M2）

> 这一期把 v0.1 的"一片 8km 的方块海"换成"一块一块拼起来的大西洋"，
> 并且让玩家能**看见**自己把未知变成已知的过程。
> 对应 `docs/13-v0.5开发计划.md` 的 M2 卡片；不变的项目约定在根目录 `AGENTS.md`。

---

## 1. 这一期解决什么

v0.1 的世界是**一个** 8000×8000 的方块：一座圆岛、一处暗礁、一条洋流带，
全部写在 `data/world/test_sea.json` 里，`Sea` 直接读它。

到了 v0.5，世界要变成"四艘船在同一个大西洋上"：

| 要长出来的东西 | 这一期做了什么 |
|---|---|
| 世界不再是一块 | `WorldMap`：16km × 16km 的 tile 网格（3×3 = 48km 可航区） |
| 地形不再只是一座岛 | 地形原语从"一个圆"变成**圆 + 带子**两种，装得下海岸线与群岛 |
| 玩家要知道自己在哪 | 手绘大西洋海图 + 未探索区域起雾 + 真实日期 |
| 相机要能一路拉远 | 同一台相机从船舱连续拉到海图（地形淡出、海图符号淡入） |

**地理怎么压缩的**：真实的塞维利亚→巴西约 6000km。v0.5 把它压进 48km 的海区，
但**船速与时间是真实比例**（60 吨拉丁帆船 5–7 节）。四个港按真实的相对方位摆：
伊比利亚在东北、加那利居中、佛得角在西南、巴西在最西边，西非海岸从北往南、
再从东边包回来。所以这一期的"跨大西洋"是**空间压缩、时间诚实**的。

## 2. 只有两个地形原语

`scripts/geom2d.gd`：

```
circle —— 圆：center + radius_m            （岛、暗礁、港口）
band   —— 折线 + 半宽：points[] + half_width_m（海岸、洋流带、礁脉）
```

这两个形状**同时**被三方使用，这是刻意的：

1. `WorldMap` 的地形查询（`is_land / is_beach / is_dry_land / is_reef / is_port /
   current_at / lee_factor / poi_at`）；
2. `ShipDynamics` 的陆地碰撞（`land_shapes` 是一份纯数据形状表，
   不是回调 —— 回调会捕获外部对象、形成引用环，v0.1 已经踩过）；
3. 视图与海图（`Geom2D.draw_shape / draw_shape_outline`）。

**为什么坚持同源**：甲板外形与船壳轮廓必须同源是铁律 4；海岸线与海图轮廓
是同一件事的另一面 —— 手绘第二份海岸线，迟早会和"船能不能开过去"的那份对不上。

### 2.1 老数据原样能读

`data/world/test_sea.json`（v0.1 的迷你海域）一个数都没改：
`island / reef / current / port` 四个块在装载时被翻译成同一种 features，
于是**同一个查询路径**既跑大西洋也跑 8km 海域。
`test_world` 的 62 项断言原样通过，这是"换一层实现"而不是"重写世界"的判据。

> ⚠️ 一个踩过的坑：老的 `port` 与 `island` 里 `from` / `to` 永远是空数组，
> 所以"是不是带子"不能只看 `has("from")` —— 那样圆岛会被当成"半宽 0 的带子"，
> 全世界的 `is_land` 一起变成 false。见 `WorldMap._shape_of`。

## 3. 分块：tile 只是索引，真源是全局坐标

**这一期的头号硬指标**：同一坐标，无论从哪个 tile 采样，结果必须完全一致。

它不是靠"小心"实现的，而是靠**构造**：

1. 所有特征都用**世界坐标**写一份（`data/world/atlantic/geography.json`）；
2. tile 只是**空间索引**，按特征的**影响范围**登记（见下）；
3. 查询只看"这个点"，tile 只决定"算哪些候选"；
4. 关掉索引全量扫描，结果必须**逐字段精确相等**（`WorldMap.force_full_scan`）。

### 3.1 按"影响范围"登记，不是按"外形"

背风区的范围是 `extent × 3`（v0.1 的圆岛公式就是 `r × 3`）——
**它在岸外，不在岸里**。如果索引只按外形登记，站在岸外 2 公里、明明在背风区里的点，
跨块时会突然读不到那块陆地的影子：地形就在缝上"跳"了一下。

```
influence_aabb(feature) = aabb(shape) 再往外放 (extent × 3)   # 只对 land
```

`tests/test_worldmap.gd` 会按影响范围核对"每个形状都登记进了它碰到的每一个 tile"，
并把索引版与全扫版在**全图 4700+ 个采样点**上逐字段比对。

### 3.2 缝上的画面证据

`39_seam_before` / `40_seam_after` 两张截图：船贴着伊比利亚南岸从 tile 2,0
开进 tile 1,0，**海岸线在虚线的缝上连续不断**。虚线只是"这里有一条块边界"的提示，
地形本身没有任何断口、没有发白、没有重影。

## 4. 海图与雾

`scripts/chart_view.gd`。三条设计：

1. **不是另一个场景、不是另一个相机**：它画在同一个世界坐标里（世界米 × 0.5），
   和地形、和船共用一套变换，所以永远对得上。滚轮拉远时地形淡出、海图符号淡入
   （`CHART_FADE_HI = 0.45` → `CHART_FADE_LO = 0.16`）。
2. **符号与地形同源**：海图上的海岸线就是 `Geom2D` 画的那两个形状。
3. **雾按 16km 分块铺**：`Voyage.discovered` 里没有的 tile 一律盖住。

### 4.1 发现规则

```
瞭望视野 = 8000m = 半个 tile
一个 tile 被"看见" = 船到这块方块的矩形距离 ≤ 8000m
一块陆地被"认得名字" = 船到它的骨架距离 ≤ extent + 8000m
```

因为视野是半个 tile，**跨块之前邻块就已经亮了** —— 不会出现"开过界了地形才冒出来"。
雾只会散不会重新聚起来；发现记录属于 `WorldState`（房主权威），进存档。

### 4.2 看过与没看过

- 没认得的陆地：**连名字都不写**（不剧透）；
- 没探明的分块：整块盖住（地名、航段一起盖）；
- 航段（`data/world/atlantic/routes.json`）：只有两头的港都发现过才画虚线。

## 5. 日期

`VoyageJournal.date_of / date_cn / clock_of_day`：

- 起点 `1519-09-20 00:00`；
- **儒略历**（格里高利改历是 1582 年）：闰年 = 能被 4 整除，没有 100/400 两条例外；
- 海图、HUD、结算页、航海日志条目全部按日期记。

> **M4 起日历按"真实航程"翻页**：地图是压缩过的（48km ↔ 6000km），
> 船按真实速度在图上走，但日历要乘压缩系数 —— 于是圣卢卡尔到加那利
> （图上 8.5km、1.7 个游戏小时）是 **4.8 个航程日**，整趟塞维利亚→巴西 ≈ 27 天。
> 系数写在世界数据里（`real_km_per_map_km: 125`），
> 换算在 `VoyageJournal.voyage_time_scale`；迷你海域没有这个字段，默认 1.0。
> 细节见 `docs/17` 第 1 节。

## 6. 接口：签名不变，实现换掉

`docs/13` 第 5.2 节把这条写成硬要求，M2 照做：

```gdscript
# scripts/sea.gd —— 还是这七个名字和签名，里面换成了 WorldMap
is_land / is_beach / is_reef / is_port / current_at / lee_factor / poi_at
```

额外补的老接口：`size_m / in_bounds / island / port / pois / poi_at / describe`。
所以 `Voyage`、`sea_debug.gd`、`test_world` 的调用点**一处都不用改**。

多岛之后必须改的两处（都不是接口，是"单岛假设"）：

| v0.1 的写法 | M2 的写法 |
|---|---|
| 陆地 = 一个圆心 + 一个半径（`land_center/land_radius`） | 陆地 = 一串纯数据形状（`land_shapes`，只写进 `ShipDynamics`，不持有 WorldMap） |
| 登陆点 = 固定的那个登陆航标 | 登陆点 = **船旁边最近的那段岸**（`WorldMap.nearest_shore`） |

## 7. 怎么验证

```powershell
& $g --headless --path . --script res://tests/test_worldmap.gd   # 80 项
```

八节：

1. **大西洋数据**：3×3 个 16km tile、48km 见方、四港、五块陆地、两处礁、两条流、三段航段；
2. **数据自检**：四个港都在水里且离岸 < 3km、四个地标都在陆地上、
   **三段航段每 250 米采样一次都不穿干地**（顺手证明"港口之间真的开得过去"）；
3. **索引等价（头号硬指标）**：全图粗网格 + 缝上的一圈点，索引版与全扫版逐字段精确相等；
   并核对"每个形状都登记进了它碰到的每一个 tile"；
4. **缝上无断口**：两条洋流真的横跨 x=16000 的缝，缝两边都摸得到它；
   人造小世界里放一条**压在缝上**的岸 —— "按形状中心归块"那类索引会当场露馅；
5. **海图与雾**：开局只亮身边那几块、雾只会散不会聚、走到跟前才认得名字、发现记录进存档；
6. **日历**：跨月、跨年、儒略历闰年（1520-02-29）、时钟跟着游戏时间走；
7. **老海域不退化**：8km 迷你海域走同一套代码，读数一个不差。
8. **真航程**：从外海真的开进登陆距离（1965 秒游戏时间、离岸 419 米）、
   **一次都没蹭滩**、路上瞭望员报告了陆地（第二幕能落下来）、上岸后走得到内陆遗迹。

画面证据（`-- shots`）：`38_chart_fog`（整张海图与雾）、`39_seam_before` / `40_seam_after`
（跨块不跳变）、`41_chart_explored`（走完一趟之后的海图）。

## 8. 已知限制（留给后面）

| 限制 | 说明 | 什么时候再说 |
|---|---|---|
| 48km 是压缩过的 | 真实 6000km；时间诚实、空间不诚实 | 不改 —— 这是 v0.5 的范围决定 |
| 海岸是"粗带子" | 没有海湾、河口、岛链 | 需要时再加原语（多边形） |
| 洋流是常数带 | 没有季节性、没有赤道逆流 | M7 自然环境 |
| 港口只是个圈 | 能停靠，但还不能补给/买卖/修船 | M4 |
| 别人的船 | 这一期世界里只有自己一条船 | M3 |
| 海图不能点 | 拉远到海图尺度之后，左键仍然是"设目标点"（能用），但没有"在海图上插旗/记航线" | M7 航线系统 |
