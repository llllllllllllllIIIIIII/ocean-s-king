# 船员系统（Day 5 定稿）

> 40 个人在一艘 24×7×4 的船上过日子：会饿、会累、会抱怨，
> 自己走到岗位上干活，**而且他们干得好不好直接决定船灵不灵**。
> 这是"玩家不直接操船"这条设计（docs/01 支柱 3）的另一半。

---

## 1. 双层模型（docs/01 支柱 4）

| | 12 名关键船员 | 28 名普通船员 |
|---|---|---|
| 数据 | `data/defs/crew_12.json` 逐个写死：姓名、职位、原文、六项技能、性格、初始关系、工作优先级 | 只有岗位（水手 16 / 见习 8 / 侍童 4）+ 按编号摊开的技能 |
| 表现 | 会饿会累会**抱怨**，日志里有名字 | 默默干活，不说话 |
| 画面上 | 大一圈、带深色描边 | 小圆点 |

**静态数据进 JSON，会变的状态只在内存**（AGENTS.md 铁律 1）：
姓名/技能/性格/关系/优先级是数据；心情/疲劳/饥饿/健康/当前位置/当前工作全在
`CrewMember` 对象里，不进任何文件。

六项技能：`seamanship`（操帆/水手活）、`navigation`、`helm`、`cooking`、`medicine`、`repair`。

---

## 2. 需求循环

```
饿  → 到 0.70 就放下手里的活去厨房（L1 灶台旁）→ 到 0.95 还在饿就会抱怨
累  → 到 0.78 回铺位睡觉                     → 到 0.95 还在干活就会抱怨
不在班 → 回下层甲板休更（回一点疲劳，比睡觉慢）
```

阈值与速率在 `crew_12.json` 的 `needs` 段。速率调得很小：一局游戏里应该是
"慢慢显出来"的压力，而不是几分钟就全员趴下。

---

## 3. 工作优先级与派活

每个关键船员有一张表：`{sail, helm, lookout, cook, repair, chores} → 0..3`
（0 = 不干，1 = 优先，2 = 一般，3 = 有空才做）。玩家在**船员面板（C）**里直接改。

每 **2 秒**重排一次活（水手长不是每帧都在喊人）：

1. 需求优先：谁饿/累到阈值，谁就去吃饭/睡觉（其它活都放下）
2. 按工作类型依次挑人：优先级高的先挑，同级看技能，再看谁没那么累，
   最后用 id 哈希做稳定的并列打破（保证同一批人每次排出来的顺序都一样）
3. 没被挑上的回舱休更
4. **只应用变化**：工作和站位没变就不动 —— 每帧清空重派会让所有人的路线
   每 0.5 秒清零，谁也走不到岗位（Day 5 现场踩到的坑）

每种工作要几个人是硬编码在 `_assign_jobs` 里的（操帆的人数由玩家的"调人员"给）。

---

## 4. 船内寻路

`scripts/ship_path.gd`：在 `(层, x, y)` 上做 BFS。

* 能走的格子 = `tiles.json` 说能走 **且** 上面没有挡路物件（桅杆/木桶/箱子/铺位…）
* 跨层 = `ship.json` 的 `links`（3 个梯子 + 1 个舱口）
* **站位从数据推**，不写死：桅杆旁边是操帆位、舵柄旁边是掌舵位、
  灶台旁边是伙房位、`kind == "platform"` 的层是瞭望台
* 开局先算一遍"从主甲板走得到哪些格子"，**站位只从可达格子里选** ——
  压舱石舱是封死的（真实帆船也这样），派活不能派进死胡同

格子只有 24×7×4 = 672 个，BFS 便宜到可以给 40 个人实时算。
走路 1.6 格/秒，爬梯子 0.6 格/秒。

## 5. 船员 → 操船：这条线在哪焊上（最重要的一节）

```gdscript
# scripts/crew.gd（操船的执行层）每帧开头：
if roster and roster.ready:
	hands_on_sails = roster.sail_hands()      # 此刻真的站在操帆位的人数
	skill          = maxf(roster.sail_skill(), 0.03)
	fatigue        = roster.sail_fatigue()
```

于是：

* 没人操帆（都被派去别处 / 都在睡觉）→ 收放速度趋近 0，帆收不动
* 新手在操帆 → 收得慢、收不准（偏差大）
* 水手长被调走 → 平均手艺掉一档，换舷时间明显变长

实测（`tests/test_crew.gd`）：关键船员参与操帆时平均手艺 **0.71**，
把他们全调走只剩水手时 **0.59** —— 而且这只是"技能"这一项，
疲劳与人数的影响更大。

## 8. 已知粗糙处

1. **没有碰撞**：几个人可以站在同一格（铺位旁边挤一堆）。视觉上能接受，物理上不真实。
2. **没有值班表**：休更只是"没被派活"，不是真的按更次排班。
3. **技能不会成长**：干久一点应该更熟练，Day 5 没做。
4. **普通船员不参与需求循环**：他们会累（数值照涨）但不会主动去睡、去吃 ——
   12 人 vs 28 人的差异就体现在这里。
5. **舱内的寻路只到"格子"**：没有把铺位/灶台当成可交互物件（人站在旁边就算在用）。
