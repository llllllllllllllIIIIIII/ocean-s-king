## 1. 这一版要做什么

**一句话**：把"四个船长在同一个大西洋上走完一段航程"，变成
**一支远征船队从 1519 年出发、绕地球一圈、1522 年带着一份历史评价回来**。

### v1.0 完成时，能演示什么

1. 单人（1 人 + 3 条 AI 船）或联机（2–4 人各一条船）从圣卢卡尔出发，**逐段开到**巴西、
   麦哲伦海峡、横渡太平洋、到香料群岛、绕过好望角、回到西班牙 —— 全程可航，不是海图上的几个点；
2. 海上会**真的打起来**：实时舷炮齐射、链弹打帆、硝烟遮视线、接舷跳帮；
3. 葡萄牙会**追捕**你：被发现 → 跟踪 → 警告 → 驱逐 → 拦截 → 攻击，你能跑、能谈、能打、能骗；
4. 三年里四十个人会饿、会病、会闹、会逃、会叛；规矩十条管得住一部分，管不住另一部分；
5. 走到最后拿到一份**船队级五类成果**，加上**四档结局** —— 完成环球，不一定是成功的远征。

### 与 v0.5 的关系

v0.5 立住了四条地基：**状态三层**（docs/14）、**世界分块**（docs/15）、
**局域网权威**（docs/16）、**指挥链路 + 陆战火器**（docs/09、docs/19）。
v1.0 **一次都不推翻它们**：

| v0.5 的地基 | v1.0 怎么用 |
|---|---|
| 地图压缩 1 km = 125 km | 直接用到全球：**320 km × 160 km = 200 块 tile**，几何比例一个数不改 |
| `WorldMap` 的 tile 索引 + circle/band 原语 | 只往里加全球海岸线数据，**查询签名不变** |
| 状态三层与星型网络 | 只加字段与消息（docs/22 第 4 章），拓扑不变 |
| 指挥链路（玩家→航海官→船员→帆） | 三年远征里它是唯一的操船方式，不改 |
| 陆战的实时小队 + 火器弹道 | **舷炮海战直接复用这套框架**（炮组当单位） |

### 为什么 v1.0 要排这么多期

v0.5 让原设定 44 节里的约 28 节有了落地（22 节完整 + 6 节部分实现）。
v1.0 要动的是 **31 节**（逐节对照在 `docs/22` 附录 A 与本文件第 13 节）——
其中一部分是把那 6 节"部分实现"补齐，其余是从零新做；
另外 12 节完全不用动、1 节只体现在文档里。
其中两个是"不确定性 ±50%"的大块：**M10 实时舷炮海战**与**M13 太平洋的长期远征**，
所以它们排在内容期之前 —— 与 v0.5 把 M3（网络）M6（陆战）提前是同一个道理。

## 2. 已锁定的产品决定

### 2.1 v0.5 的十七条继续有效（`docs/13` 第 2 节，一条都不许悄悄改回）

规划范围到 v1.0（不是"再做一版"）· 里程碑制 · Windows zip 放 Release · 联机 2–4 人 ·
四艘远征船（玩家顶替 AI）· 联机是核心 · 房主管世界、每船本机模拟 · 随时加入 / 掉线转 AI /
重进接管 · 大西洋海图 + 局部海域无缝拼接 · 中文写死 · SVG 部件管线 + CC0 音频 ·
陆战实时小队 · 火器硬指标 · 火炮范围（陆战 + 船对岸）· 全队共同结算 · 尽量贴合史实 ·
状态分层是地基

### 2.2 v1.0 新增的六条（2026-10-02 拍板）

| # | 决定 | 内容 |
|---|---|---|
| 1 | **海战形态** | **实时舷炮海战**（炮组为单位 + 接舷战），复用陆战框架，不做"卡片结算式"海战 |
| 2 | **环球颗粒度** | **全程逐段可航**：整个地球的海域都能开（320 km × 160 km / 200 块 tile），手工内容集中在关键区域，远洋空海是程序化生成的低事件洋面 |
| 3 | **联机定位** | **仍是核心**：2–4 人各一条船，单人 = 1 人 + 3 AI，新系统一律考虑联机 |
| 4 | **时间尺度** | **历史尺度约三年**（1519-09-20 → 1522-09-06），日历真实推进，新增 ×144 快进档 |
| 5 | **船队与控制** | **旗舰沉没可换船**（联机时沉船者接手另一条）+ **轻编队**三条指令（跟随/保持/自由） |
| 6 | **交付标准** | **可发布的完整游戏**：Windows zip + GitHub Release，中文写死；**不含 Steam** |

**合计 90–138 天（约 4–6 个月，6h/天）。** 不确定性最大的两期是 M10（海战，±50%）
与 M13（长期远征与季节，±50%）。

**关键路径**：M9（世界）→ **M10（海战）** → M11（势力）→ M12（南美）→
**M13（太平洋）** → M14（印度洋）→ M15（归乡）→ M16–M18（深化）→ M19（结局）→ M20（发布）。
M16–M18 三期的输入都在 M11–M15 之后，彼此比较独立，可以在需要时调序或并行。

> **每一期结束必须有一个能跑的版本。** 宁可功能少，不可功能坏 —— 这条从 v0.1 沿用。

## 4. 分期详细卡片

### M9 · 全球海图地基

**目标**：把 3×3 块的大西洋，换成**整个地球的 320 km × 160 km**，
并且让"同一坐标在任何 tile 采样结果一致"这条硬指标在 200 块上依然成立。

**任务**

| 项 | 内容 |
|---|---|
| 数据格式 | `data/world/global/*.json`：大陆海岸线（长 band 折线）、岛群（circle）、海峡、暗礁、洋流带、季风带；沿用 circle/band 两个原语，**不加多边形** |
| 全球索引 | 20×10 = 200 块 tile；索引仍按**影响范围**登记；`Sea` 的七个查询**签名一字不改** |
| 分区图幅 | 全球海图 = 一张 320×160 的总图；关键区域各有放大图幅（伊比利亚 / 加勒比 / 海峡 / 太平洋岛链 / 香料群岛 / 好望角） |
| 预载 | 相机拉远到底看到全球图；玩家在局部视图里开到 tile 边界时相邻 8 块已预载 |
| 航线数据 | `routes.json` 从 3 段扩到全球分段，每段带 `real_km_per_map_km`（高纬度修正）、风险/补给/价值 |
| 快进 | 新增 **×144** 档（现有 ×1/×4/×12/×36 之上） |

**产出物**：`data/world/global/*.json`、`scripts/world_map.gd` 的全球索引、`scripts/chart_view.gd` 的分区图幅、`tests/test_globalmap.gd`、一组跨洋截图。

**验收标准**

1. `tests/test_globalmap.gd`：全球航线上的采样点（每 250 米）在**索引版与全扫版**下逐字段相等；
2. 一条命令无头跑"圣卢卡尔 → 摩鹿加"的航线，不出现"必须穿陆地"的缝、不出现地形跳变；
3. 全球 200 块的索引构建耗时与内存有数字（写进实际记录），远洋空海的 `test_perf` 不高于基线；
4. 既有 20 条通道全绿（`test_world` 的迷你海域回归不许退化）。

**砍单预案**：关键区域手工 + 其余海域用一个极简的全球陆地掩码；
海图只做一张总图不加分区图幅；`real_km_per_map_km` 全局一个数。

**这一期的第一个动作**

1. 先确认 v0.5 那三件事的状态（发 Release / 真人试玩 / 双机）；
2. 跑一遍本文件第 1 节的基线，确认全绿；
3. 把 `Sea` 的七个查询从"只认大西洋特征"扩到"认全球特征"，**先立全球数据文件与索引，再填内容**。

### M10 · 海战（实时舷炮 + 接舷）

**目标**：让"海上打起来"是真的打起来 —— 炮组、装填、弹种、距离、机动、硝烟、跳帮。

**任务**

| 项 | 内容 |
|---|---|
| 炮组单位 | 一门炮 + 2–4 人 = 一个炮组；装填进度独立；炮组人数与技能决定装填速度 |
| 弹种 | 实心弹（打结构）/ 霰弹（打人）/ 链弹（打帆索）；真源进 `weapons.json` |
| 命中 | 技能 × 距离 × 相对运动 × 天气查表 + 确定性偏差（**不用随机数**） |
| 七处损伤 | 船壳 / 桅杆 / 风帆 / 舵 / 货舱 / 弹药区 / 起火进水，全部复用既有链路（docs/22 第 5.4 节） |
| 接舷 | 钩住 → 跳帮人数 → 在两条甲板上打一场（**复用 `land_battle.gd` 的框架**） |
| 硝烟与视野 | `visibility_m` 下降，并且**寻敌真的受它限制**（v0.5 的已知限制，这一期补上） |
| 权威归属 | 开火方广播"谁向谁开火"，**受击方权威判命中并广播结果** |
| 离线标定 | `tools/weapons_prototype.py` 扩到舷炮；生成命中率查表 |

**产出物**：`scripts/naval_battle.gd`（新）、`scripts/guns.gd`（新）、`data/defs/weapons.json` 扩展、`tests/test_naval.gd`、双进程对打的一组断言、一场遭遇的截图。

**验收标准**

1. `tests/test_naval.gd`：**四条硬指标**全绿（装填不下于真源 / 齐射 ≥ 各自为战 1.8 倍 / 接舷决定近战 / 弹种不能互换）；
2. 无头可复现：同样的初始条件跑两遍，轨迹与伤亡名单完全一致；
3. 双进程：两边对打一场，伤亡名单与七处损伤一致；
4. 单机：被海盗截击能进战斗、能打、能跑；打完的伤亡进讣告与结算；
5. 既有 20 条通道全绿（尤其 `test_land_battle` 不许退化 —— 接舷复用了它）。

**砍单预案**：先做船对船的舷炮对轰（不含接舷），链弹不做；
接舷战降级为"两边人数与近战质量结算一次"（不进甲板逐人打）。

**这一期的第一个动作**

1. 跑 M9 的通道；
2. 写 `weapons_prototype.py` 的舷炮部分，**先在离线扫参数**（与火器同一套路：先模型，再进游戏）；

### M11 · 势力 · 追捕 · 外交

**目标**：世界不再只有风和礁 —— 有人、有势力、有政治。

**任务**

| 项 | 内容 |
|---|---|
| 势力真源 | `data/defs/factions.json`：六类势力（西班牙王室 / 葡萄牙 / 当地文明 / 商人 / 海盗 / 其他航海者）+ 态度阈值 + **王室命令表** |
| 葡萄牙追捕 | 六环状态机：被发现 → 跟踪 → 警告 → 驱逐 → 拦截 → 攻击；甩掉、谈判、伪装、改线、战斗五条应对 |
| 当地文明扩 | 从"一个文明一条记录"扩到**多群体各一条**（同一文明内部可以态度不同） |
| 王室命令 | 3–5 条硬指标（开局摊开给玩家看），完成/违抗都进世界记忆与结局档位 |
| 抽象 NPC 船 | 商人/海盗/其他航海者的航线与遭遇（复用 `abstract_ship.gd` 的形状） |
| 世界记忆扩读者 | 记忆的读者扩到势力态度、王室评价、当地文明、结算与结局 |

**产出物**：`data/defs/factions.json`、`scripts/factions.gd`（新）、`scripts/pursuit.gd`（新）、`culture.gd` 多群体化、`tests/test_factions.gd`、追捕链的无头复现。

**验收标准**

1. 追捕六环：每一环有可复现的进入条件；三条应对（甩掉 / 谈判 / 打）各一组断言；
2. 态度链：一次行为 → 态度值变化 → 跨阈值换档 → 港口/贸易/遭遇行为变化；
3. 多群体：同一文明的 A 群敌对、B 群友善时，行为分别符合各自态度；
4. 王室命令：每条命令的"完成"与"违抗"两条路径都能走到，且体现在结局档位里；
5. 联机：势力态度与追捕环由房主推进，客户端看到同一个值（双进程对账加一组）。

**目标**：把 v0.5 的终点（巴西）接上太平洋入口 —— 逐海里开过去，中间有岸上内容。

**任务**

| 项 | 内容 |

| `ShipState` | `guns`（炮位/炮种/弹药就绪/装填进度）、`boarding`（接舷状态）、`flagship`（旗舰身份与可转移否）、`damage` 扩到七处、`hazard`（起火/进水状态） | 拥有者 |
| 细化运行时 | 不变（永不过网） | 拥有者 |

**硬规矩**：新字段一律进对应类的 `capture_state()` / `apply_state()` 与 `FIELDS` 契约；
漏一个，`test_save` 的字段覆盖断言会当场报出字段名（v0.5 立的护栏）。

### 5.2 世界查询：签名不变，实现换掉（沿用 `docs/15` 的做法）

`Sea` 的七个查询（`is_land / is_beach / is_reef / is_port / current_at / lee_factor / poi_at`）
**名字与签名一个都不改**，实现从"只认大西洋特征"扩成"认全球特征"。
这样 `Voyage`、`sea_debug.gd`、`test_world` 那一批调用点都不必重写 ——
风险从"重写世界"降到"替换一层实现"。**硬指标仍是：同一坐标在任意 tile 采样结果完全一致。**

### 5.3 网络消息（真源在 `scripts/net/net_protocol.gd`）

| 新消息 | 方向 | 说明 |
|---|---|---|
| `fire` / `hit` | 开火方 → 受击方权威 → 全部 | 海战：谁向谁开火；命中与伤亡由受击方权威广播 |
| `board` | 接舷双方 → 房主 → 其他 | 钩住、跳帮人数、结果 |
| `faction` | 房主 → 全部 | 势力态度与追捕环变化 |
| `formation` | 客户端 → 房主 → 全部 | 编队指令 |
| `flagship` | 房主 → 全部 | 旗舰转移宣布 |
| `trade_req` / `trade_ack` | 客户端 ↔ 房主 | 两段式交易（申请 → 执行 → 回执） |

**协议版本不符仍然直接拒绝**（与存档同一个口径：不承诺兼容，但要说人话）。

### 5.4 三条权威规则（v1.0 扩到海战与船队）

1. **谁的船谁写**；2. **世界只有房主能改**；
3. **命中与伤害由"受击方所属的权威"判定** —— 陆战与海战都是这一条；
4. 旗舰转移由**房主宣布、拥有者执行**（房主是唯一知道"哪条船还在"的人）。
