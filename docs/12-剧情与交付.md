## 1. 三幕：触发条件 + 文本 + 后果

docs/01 支柱 6 写死了顺序：**出港学操帆 → 发现岛并抉择是否登陆 → 返航结算**。
顺序本身就是设计，所以 `Story` 一次只推进一幕（`head + 1` 满足条件才落下一幕），
不存在"跳过第一幕直接结算"这种事。

| 幕 | 触发条件（`trigger`） | 给玩家的目标 | 后果（`effects`） |
|---|---|---|---|
| 第一幕 · 出港 | `start`（开局） | 朝东左键点一个目标点 | 写日志 + 弹消息 |
| 第二幕 · 绿岬岛 | `flag: island_known`（瞭望员报告） | 开到滩头 → X 抛锚 → L 挑人登陆 | 写日志 + 弹消息 |
| 第三幕 · 返航 | `returned_home`（见过岛 **且** 船进港区） | 读结算（R 再走一趟） | 写日志 + 定下收尾句 + **宣布可以结算** |

触发条件的种类目前有四种，都在 `Story._met()` 里：

```gdscript
"start"          开局
"flag"           某个旗标（"island_known" 直接读 Voyage，其余读 Voyage.fired）
"elapsed"        t >= seconds
"returned_home"  见过岛 + 船在港口半径 + radius_m 以内
```

**后果只有五种，全是"纸面上的事"**：`journal` / `last_line` / `message` / `flag` / `objective` / `ending`。
剧情**不能**改船的速度或位置 —— 铁律 5，`tools/check_motion_ownership.py` 每天都在查。
想让剧情影响航行，只能通过已经存在的玩法入口（比如 `voyage.gd` 里那条"风向突变"）。

### 第二幕的抉择是双向的

docs/01 说第二幕是"发现岛并**抉择**是否登陆"。所以"不登陆"也必须是一种被系统承认的答案：

```gdscript
# voyage.gd：见过岛之后又把它甩在船尾 —— 那就是决定不上岸
if island_known and not fired.has("landed") and pos.distance_to(_island_center()) > 3200.0
```

两条路都会把目标换成"返航：把船开回出发港"，也都会在结算页上留一条决定。
第一版只处理了"登陆"这一半，玩家要是绕过去，结算页会写"你没有做过一个需要负责的决定"——
那就等于**系统不承认玩家做的决定**，是这一页最不该犯的错。

## 2. 引导：只教三件事，而且都要能被验证

陌生人最容易误解的一点是"我为什么不能自己开船"。所以开场标题卡直接把这句话写在脸上：

> 你不能自己掌舵，也不能自己拉帆 —— 十六世纪的船长也不干这些。
> 你只指一个方向：航海官挑航法，水手去调帆，船才动。

| 教学步骤 | 什么时候露出 | 怎么算完成 |
|---|---|---|
| 左键点一个目标点 | 第一幕 | `orders.has_target_point` 变成 true |
| 按 Tab 打开帆态面板 | 第一幕 | 面板真的被打开过（`story.note("open_sail_panel")`） |
| 在抢风里待满 5 秒 | 第一幕 | `nav.method == BEAT` 累计 ≥ 5 游戏秒 |
| 开到滩头抛锚登陆 | 第二幕 | `voyage.ashore` 或 `fired["landed"]` |

规则：**每一步都得有"能被数出来"的完成条件**。写不出完成条件的引导，就是一个关不掉的弹窗。

界面上一共四块，每块只回答一个问题：

```
左上【这一幕】  我现在该干什么？教学做到第几步？
中上【剧情卡】  刚才发生了什么？（新的一幕落下来时出现几秒，右边并排，不盖目标卡）
左下【船的状态】船怎么样？人在干什么？快进到几倍了？
底部【消息条】  刚刚船上报了什么？
```

## 3. 航海日志 → 结算页

结算**不是另写一段文案**，而是把文书（Escribano）记了一路的那本日志摊开。
所以玩家看到的一定是自己真的干过的事：

```
【到过的地方】  每到一个地标就记一条（滩头 / 遗迹 / 溪流 / 村落）
【你做的决定】  登陆带了几个人、撞没撞礁、有没有和部落动手、有没有绕过岛
【船与人】      三处损伤、人在船上还是岸上、累得最狠的是谁
【文书最后写下的一条】  剧本给的收尾句
```

数据来源：`VoyageJournal.record / decide / landfall / advance`，
分别对应"事件""决定""地标""航程"。**航程会过滤瞬移**（单帧位移 > 5 米不算），
否则测试与截图脚本一 `set_pose`，航程立刻变成几千公里。

## 4. 节奏：8 公里的海怎么在 15 分钟里走完

这是这一天唯一需要"算"的验收。实测（`tools` 之外，跑在 `tests/test_story.gd` 里）：

| 段 | 游戏时间 |
|---|---|
| 出发港 → 滩头 | 23.5 分钟 |
| 滩头 → 出发港 | 20.6 分钟 |
| 合计 | **44.2 分钟** |

×12 快进 = **3.7 分钟真实时间**，剩下 11 分钟留给读开场、看帆态、上岸、读结算。

一开始想用"按住 `.` 加速"，但让玩家按住两分钟只会让人烦；改成 **`. 键循环 ×1 → ×4 → ×12**，
而且倍数一直摆在左上角的目标卡里。

⚠️ 快进**不是把 `dt` 乘大**。物理步长永远是 `SIM_DT = 0.05` 秒，
快进只是每帧多跑几步（`SeaDebug._tick_sim`）—— 步子一粗，气动立刻飘。

## 5. 这一天踩到的坑（全部已修，且都有回归断言）

| 坑 | 症状 | 修法 |
|---|---|---|
| 回船只清了关键船员的上岸标记 | 6 名水手永远挂在岸上，船此后一直少 6 双手，结算页还写"岸上还有 6 人" | `_finish_boarding()` 清**所有** `roster.members`。Day 6 的测试只查了 12 名关键船员，所以一直没露出来 |
| 第三幕的目标永远显示不出来 | 到港那一刻才触发第三幕、才写"回出发港"，玩家在到港之前不知道要回港 | 第二幕的抉择一做完就把目标换成返航（`Story._update_objective`），海图上同时画出返航虚线 |
| 消息条按游戏时间消失 | ×12 快进下"12 秒的消息"只亮 1 秒 | 界面计时搬出 `tick()`，改成 `voyage.tick_ui(真实 delta)` |
| 中文不换行 | 剧情卡的一行文字直接冲出面板糊在屏幕上 | `draw_multiline_string` 默认只在**词边界**断行，中文没有空格 → 整段是一个超长单词。必须显式加 `BREAK_GRAPHEME_BOUND` |
| 半透明底把 HUD 透出来 | 标题卡上能看到左上角的目标卡和右下角的风玫瑰，像两个界面糊在一起 | 幕间（标题卡 / 结算页）摊开时把航行界面整层 `visible = false` |
| `nav.tack_count` 永远是 0 | 帆态面板上的"换舷 N 次"从来没动过 | 原来的判断写在一个**永远进不去的分支**里（外层已经要求 `method != _last_method`）。修好后拆成两个数：抢风 **段数**（一定有）与换舷 **次数**（看航线） |
| 截图里两个面板都是空的 | 改了状态当帧就截 | 老坑重犯一次：剧情卡要等 `_update_hud` 灌数据、再等一帧才画得出来。改完状态**隔一帧**再截 |
