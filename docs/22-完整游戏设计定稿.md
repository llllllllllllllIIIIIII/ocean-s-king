| 标注 | 意思 |

| **【定稿】** | v1.0 的目标口径。没实现的，落在 `docs/23` 的某一期 |

| **【不做】** | 明确划出去的东西，写在这里防止范围膨胀 |

### 0.3 三条不许动的铁律（其余见 `AGENTS.md`）

1. **任何系统都不许直接改船的速度或位置** —— 玩家 → 船员 → 帆 → 船 → 表现，单向。
2. **玩家不直接操船** —— 只选目标点/帆档/人员，航海官挑航法，水手执行。
3. **状态三层，各有唯一写入者** —— 世界归房主、每条船归拥有者、逐人细节永不过网。

## 1. 定位与三大核心

### 1.1 一句话

16 世纪麦哲伦时代的远洋航行模拟 / 探索 / 管理游戏，**2D 正交表现 + 3D 空间逻辑**。
玩家扮演一支远征船队的船长，带船队从欧洲出发、绕地球一圈、回到出发地接受评价。

### 1.2 三大核心（docx 第四十四节）

| 核心 | 在本文件里的落点 |
|---|---|
| **船** | 船是舞台：四层结构、40 人生活、资源与损伤、火器与炮位 —— 第 5、6、10、11 章 |
| **船长** | 玩家就是船长，船长在哪里、能做的事就在哪里 —— 第 6、7、8 章 |
| **世界** | 不断进入未知，把未知变成已知 —— 第 3、12、13、14 章 |

一句话：**船是基地，船长是玩家，世界是冒险。**

### 1.3 参考坐标（不是要抄它们的皮，是要它们的**结构**）

| 游戏 | 借什么 |
|---|---|
| 矮人要塞 | 分层空间与分层观察（滚轮切层） |
| 环世界 | 船员是个体、工作是优先级与规则 |
| 冰汽时代 | 资源压力、社会管理、每个选择都有代价 |

### 1.4 三条体验支柱（v0.1 定的，v1.0 不许退化）

1. **气动是唯一的动力来源**：真风 → 视风 → 帆的攻角与升阻力 → 船体阻力 + 龙骨诱导阻力 → 位姿。
2. **指挥链路**：玩家选目标点/帆档 → 航海官挑航法 → 水手调帆 → 帆的实际角度 → 船动。
   **船员技能 = 船的机动性。**
3. **"船长在哪里"是一种资源**：离开船，就暂时放弃另一边的直接控制权。

### 1.5 一局是什么样

| 项 | 口径 |
|---|---|
| 时间跨度 | **1519-09-20 出海 → 1522-09-06 归来**（1082 天的历史锚点） |
| 游戏内时长 | 约 **210 游戏小时**（其中约 64 小时在真的航行，其余是停泊、补给、岸上、事件） |
| 真实时长 | ×36 快进约 **6 小时**；新增 **×144** 档后远洋空海约 **1.5 小时** |
| 人数 | 单人 = 1 人 + 3 条 AI 船；联机 = **2–4 人各开一条船**，同一个世界 |
| 终点 | 全队回到圣卢卡尔 → 王室评价（五类成果 + 四档结局） |

【定稿】新增 **×144 快进档**（现有 ×1/×4/×12/×36 之上）。
理由：一次环球是 v0.5 的十几倍航程，只有 ×36 的话真实时间在 6 小时量级；
远洋空海本身没有操作，快进是唯一合理的压缩手段。物理步长不变（快进永远是多跑几步）。

## 2. 一次远征的完整形态（四个阶段）

四个阶段不是章节标题，是**四种不同的压力**。玩家的经验、资源、船员状态都随阶段变化。

| 阶段 | 历史时段 | 地理 | 主要压力 | 玩家的核心问题 |
|---|---|---|---|---|
| **一 · 大西洋与南美** | 1519-09 → 1520-11 | 圣卢卡尔 → 加那利 → 佛得角 → 巴西 → 拉普拉塔 → 圣胡利安 → 麦哲伦海峡 | 未知、补给不足、当地文明、叛乱与饥荒 | "我能在坏消息到来之前把船和人管住吗" |
| **二 · 太平洋** | 1520-11 → 1521-03 | 海峡西口 → 关岛 → 菲律宾 | **孤立**：约 17000 真实公里没有补给点；缺水、坏血病、长期士气 | "我不知道要走多久，怎么让四十个人活到看见陆地" |
| **三 · 香料群岛与印度洋** | 1521-04 → 1522-05 | 摩鹿加（蒂多雷）→ 巽他海峡 → 印度洋 → 好望角 | 贸易机会、葡萄牙的东方据点、内讧与损失 | "带什么回去才算没白来" |
| **四 · 归乡** | 1522-05 → 1522-09 | 佛得角 → 圣卢卡尔 | 最后一段的消耗、王室命令的执行度、政治后果 | "回到欧洲时，我交得出的是一份什么样的账" |

【定稿】**阶段只是设计叙述，不是游戏状态。** 代码里没有"阶段机"，
只有日历、位置、世界记忆 —— 阶段是它们的自然结果。理由：一个"阶段"状态会让
每一期都要去改它，而它本身不产生任何玩家看得见的东西。

### 2.1 每一段航线都必须有"取舍"

docx 第三十八节要求航线在**距离 / 时间 / 风险 / 补给 / 商贸价值 / 战略价值**之间取舍。
落地口径：`routes.json` 的每一条航段带元数据（风险、补给、价值），
玩家在港口面板与海图上就能看见 —— 这一半 M8 收尾已经做了（`docs/20` 第 5.1 节），
v1.0 只是把航段表从 3 段扩到全球。

## 3. 世界结构：海图、分块、发现

### 3.1 一张图就是整个地球（【定稿】的关键结论）

v0.5 已经定下：**地图 1 km = 真实 125 km，时间诚实、空间不诚实**（`docs/15`）。
把同一个比例用在整颗星球上：

```
地球周长  40 000 km ÷ 125 ≈ 320 地图公里
地球半周  20 000 km ÷ 125 ≈ 160 地图公里

=> 世界的坐标平面 = 320 km × 160 km
=> 16 km 的 tile 网格 = 20 × 10 = 200 块
```

也就是说：**"全程逐段可航"不需要新引擎、不需要第二个世界**。
v0.5 的大西洋是 3×3 块（48 km），v1.0 把它扩到 20×10 块（320 km × 160 km），
几何比例与航线数据**一个数都不用改**，只是特征表从 5 块陆地扩到全球海岸线。

**【定稿】这张图是圆柱，不是平面。** 环球必然要跨过一条接缝（从西往东绕回来，
经度总要回到起点），平面上做不到连续 —— 所以 x 轴**卷起来**：世界数据里声明
`wrap_x: true`，tile 索引在缝上按未卷的格子号枚举再卷回去，查询入口统一把点卷进
世界宽度，距离与位移一律**走最短的一边**（`WorldMap.delta` / `dist`）。
接缝放在 **180°**（那里没有手工特征），所以缝本身不会切坏任何一块地形。
M9 把这一层做在世界数据与查询上；**船真的开过那条缝**（积分后的 wrap、抵达判定、
AI 航点、远端插值）是 M12 的活 —— 那之前主线还开不到缝上。

### 3.2 空间压缩与时间诚实

| 项 | 口径 |
|---|---|
| 地图压缩 | 1 地图 km = 125 真实 km（等距圆柱摆放，经度按赤道比例统一） |
| 高纬度东西向被拉长 | 已知代价，最大约 1.6×（合恩角 53°S）。**用航段元数据修正**： |
| 航段修正 | 每段航线自带 `real_km_per_map_km`，日历与补给按**航段**算，不是一个全局数 |
| 日历 | 儒略历，从 1519-09-20 起（沿用 `VoyageJournal.date_of`） |
| 消耗与磨损 | 一律按**航程小时**（`damage_per_hour × 60 游戏秒 × real_km_per_map_km / 3600`） |

一次完整环球的航线总长约 **500 地图公里**（≈ 63000 真实公里），
按平均 4 节算是约 **350 个真实航行日**，与历史吻合（麦哲伦从出港到归来用了 1124 天，
其中大半花在停泊、等待与岸上）。

### 3.3 内容密度：手工锚点 + 程序化空海

"全程逐段可航"的意思是**整个地球的海域都能开**，不是"整个地球都手绘"。

| 区域类型 | 做法 | 例子 |
|---|---|---|
| **关键区域**（手工） | 海岸线用 `Geom2D` 的 circle/band 原语写死，带港口、暗礁、地标、岸上内容 | 伊比利亚、加那利、佛得角、巴西、拉普拉塔、麦哲伦海峡、关岛、菲律宾、摩鹿加、好望角、亚速尔 |
| **远洋空海**（程序化） | 只有风带、洋流、季风、天气；低事件密度的洋面 tile | 太平洋中部、南印度洋 |
| **海岸线（长条）** | 大陆用长 band 折线近似，够"船开不上去"就行 | 南美东岸、非洲东岸、亚洲南岸 |

【改写】docx 第二十三节说世界地图包括"大陆、海洋、岛屿、港口、海峡、暗礁、已知航线、
未知海域、其他船只、势力范围" —— 全部保留，但**海岸线不做多边形**：
v0.5 的两个原语（圆 + 带）够用，多边形只在出现"必须做海湾/河口"的具体需求时再加
（【不做】v1.0 不做多边形海岸）。

### 3.4 分块、雾与发现（沿用 v0.5，不重新设计）

- **tile 只是索引，真源永远是全局坐标**；同一坐标在任意 tile 采样必须完全一致（M2 的唯一硬指标，v1.0 扩到 200 块后仍然是硬指标）。
- 索引按**影响范围**登记（陆地往外放 `extent × 3`），否则背风区在缝上读不到。
- 海图：羊皮纸色陆地 + 墨线轮廓 + 未探明的整块起雾；雾只散不聚。
- **没认得的陆地不写名字**（连名字也是发现出来的）。
- 相机：同一台相机从船舱连续缩放到全球海图；屏幕恒定尺寸一律 `1/zoom` 补偿。

### 3.5 验收口径

1. 全球 200 块：索引版与全扫版在**跨 tile 缝**上逐字段相等（沿用 `test_worldmap` 的口径，采样点扩到全球航线）。
2. 一条命令无头跑"从圣卢卡尔到摩鹿加"的航线采样，不出现"必须穿陆地"的缝。
3. 远洋空海（无手工特征的 tile）下逻辑帧耗时不高于 v0.5 的 `test_perf` 基线。
4. 圆柱：坐标加一整圈是同一个点、跨缝的距离走最短的一边、接缝两边给出同一份地形。
5. **实测（2026-10-02，M9 收工）**：索引 vs 全扫在整条环球航线的 2470 个采样点上逐字段相等；
   13 段航段 2470 个采样点 0 处干地；13 个港都在水里；建索引 2.5 ms、逐点采样 30.7 µs/点。

## 4. 状态分层与联机权威

### 4.1 三层（【现状】，v1.0 只加字段、不改形状）

| 层 | 谁写 | 装什么 | 上网吗 |
|---|---|---|---|
| `WorldState` | **房主** | 时钟与日历、风、全局事件与剧情、港口库存与价格、已发现地图、知识、世界记忆、AI/NPC 抽象船 | 房主 0.5 s 广播，客户端只读覆盖 |
| `ShipState` | **那条船的拥有者** | 位姿、帆与锚、损伤、指令、航海官、船员执行层、40 人名册、登陆队、资源、规矩与社会 | 拥有者 20 Hz 广播摘要 |
| 细化运行时 | 拥有者 | 气动积分、40 人逐人需求与寻路、登陆队实时位置 | **永不过网** |

**必然推论（UI 规矩，v1.0 不变）**：别人船上没有逐人模拟，
**不允许进入别人的船的内部视图** —— 滚轮沉入船舱只对自己那艘船有效。

### 4.2 v1.0 往 WorldState 里加什么

| 新字段组 | 内容 | 为什么是世界状态 |
|---|---|---|
| `factions` | 各势力（西班牙王室/葡萄牙/当地文明群体/商人/海盗/其他航海者）的态度值与状态 | 同一条船的行为要被所有人看见，只能房主判 |
| `pursuit` | 葡萄牙追捕线的当前环（被发现…被攻击）、触发时间、目标船 | 追捕是"世界对我们做了什么"，不是某条船的属性 |
| `season` | 季节/季风档位与已持续的航程时间 | 同一片海对所有人一样（沿用天气的先例） |
| `global_knowledge` | 全球已发现的海域/港口/物种/文化条目 | 知识是"世界的已知部分"（沿用 `knowledge`） |
| `formation` | 编队指令投影（跟随谁/保持多少距离） | 编队是世界级的共享约定 |

### 4.3 v1.0 往 ShipState 里加什么

| 新字段组 | 内容 | 为什么是船状态 |
|---|---|---|
| `guns` | 炮位、炮种、弹药就绪度、装填进度 | 只有自己那条船细化 |
| `boarding` | 接舷状态（钩住谁、谁在跳帮、跳帮人数） | 同上 |
| `flagship` | 我是不是旗舰、可转移到哪些船 | 归属是船自己的属性；转移由房主宣布 |

### 4.4 权威归属的四条硬规则（前三条【现状】，第四条【定稿】）

1. **谁的船谁写**：客户端不接受别人对"我的船"的写入。
2. **世界只有房主能改**：客户端算出的风/时间/港口价格一律被覆盖。
3. **命中与伤害由"受击方所属的权威"判定**：射击方只广播"谁向谁开火"。
   v1.0 把这条从陆战扩到**海战**（舷炮与接舷都照这条）。
4. **【定稿】旗舰转移由房主宣布、拥有者执行**：房主是唯一知道"哪条船沉了、
   哪条还在"的人；宣布之后，接手方的机器把新船升为细化（沿用 `attach_player`）。

### 4.5 消息清单的增量（真源仍在 `scripts/net/net_protocol.gd`）

| 消息 | 方向 | 说明 |
|---|---|---|
| `fire` / `hit` | 开火方 → 受击方权威 → 全部 | 海战：谁向谁开火；命中与伤亡由受击方权威广播 |
| `board` | 接舷双方 → 房主 → 其他 | 钩住、跳帮人数、结果 |
| `faction` | 房主 → 全部 | 势力态度与追捕环的变化（进 `world` 也行，独立更省带宽） |
| `formation` | 客户端 → 房主 → 全部 | 编队指令 |
| `flagship` | 房主 → 全部 | 旗舰转移宣布 |

**不上网的东西**（v1.0 不变）：40 人逐人状态、烟的粒子、相机、UI 状态、别人船上的船员细节。

### 4.6 验收口径

双进程对账（沿用 `test_net_loopback`）扩到四件事：
**海战一场**（两边伤亡名单一致）、**势力态度一次变化**（两边看到同一个值）、
**换旗舰一次**（接手方拿到连续的船与名册）、**编队指令一次**（跟随命令生效且可复现）。

## 5. 船与船队

### 5.1 四艘远征船（【现状】）

`data/defs/fleet.json` 定义四艘：特立尼达 / 圣安东尼奥 / 康塞普西翁 / 维多利亚。
一个船位有三种身份：

| kind | 谁在跑 | 有什么 |
|---|---|---|
| `local` | 本机 | 气动 + 40 人名册 + 登陆队（在 `Voyage` 里） |
| `ai` | 房主 | 9 键摘要，照 `routes.json` 的航点走，撞岸贴着滑 |
| `remote` | 别人 | 20 Hz 摘要 + 100 ms 插值，**不外推** |

摘要白名单只有九个键：`id / name / pos / heading / sail_level / anchored /
hull_pct / crew_count / action`（多一个键 `test_fleet` 就报错）。
【定稿】海战时代再加两个：`guns_ready_pct`（炮组就绪度）与 `flagship`（是不是旗舰）。
**货舱里具体装了什么永远不过网**（v0.5 的规矩，继续）。

### 5.2 旗舰沉没与控制转移（【定稿】docx 第二十二节）

```
主船失去航行能力或沉没
  → 房主宣布新的旗舰（从还浮着的远征船里选）
  → 接手方的机器把那条船从摘要升为细化（attach_player 的同一套）
  → 新旗舰继承：位置/艏向/船体%/人数/货物摘要 + 按船 id 种子重新生成的名册
  → 旧旗舰：沉没（记录进日志与结算）或降为"拖带/残骸"（由玩家当时的选择决定）
```

**关键约束**：这是"故事的一部分"，不是 Game Over（docx 原话）。
单人时玩家的船沉了 → 自动接手上一条还在的船；联机时沉船的人**接手另一条没人开的船**。
【不做】把"沉船"做成一段强制过场动画 —— 用一条消息 + 结算条目表达就够。

### 5.3 轻编队指令（【定稿】，三条，不做军阵）

| 指令 | 行为 |
|---|---|
| **跟随** | 跟着指定的那条船，保持一个距离档（近/中/远） |
| **保持阵位** | 朝同一方向、保持相对方位（不是精确队形） |
| **自由巡航** | 各船自己照航线走、自己补给、自己避风 |

【不做】军阵、精确队形、旗舰信号旗系统（docx 第十九节只要求"我率领的是一支船队"的感觉）。

### 5.4 七处损伤的最终口径（【定稿】docx 第三十三节）

v0.5 做了三处（船体 / 桅杆 / 舵），并让炮击复用同一条链路。v1.0 补齐到七处：

| 部位 | 玩家看得见的效果 | 真源 |
|---|---|---|
| **船壳**（船体） | 进水、航速下降、沉没风险 | 【现状】`ShipDynamics` 的 `damage.hull` |
| **桅杆** | 帆面积上限下降 | 【现状】`damage.mast` |
| **风帆** | 独立于桅杆的航速损失（可单独修补） | 【定稿】`damage.sail`，用帆布修 |
| **舵** | 转舵效率下降、更难关进风 | 【现状】`damage.rudder` |
| **货舱** | 货物损失（进水时按比例泡掉） | 【定稿】`damage.hold` → `Cargo` |
| **弹药区** | 战斗力下降；受损后有起火/殉爆风险 | 【定稿】`damage.magazine` → `guns` |
| **起火 / 进水** | 不是"损伤值"而是**状态**：每航程小时继续恶化，要派人去救 | 【定稿】`hazard` 状态机 |

每一条都必须在上层看得见效果（铁律：损伤只准通过既有链路表达），
并且**全部复用**气动/操船那三处，不新开一套物理。

### 5.5 验收口径

1. 旗舰沉没 → 玩家仍在游戏里、新船能开、旧船记进日志与结算。
2. 联机：沉船的一方接手另一条船，其他人看到的是"他换了一条船"，不是"他掉线了"。
3. 编队指令：跟随/保持/自由三条都能无头复现（给同样的初始条件得到同样的轨迹）。
4. 七处损伤：每一处都有断言证明"上层看得见"（阻力/帆面积/舵效/货物/炮组/持续恶化）。

## 6. 指挥链路与四十个人

### 6.1 指挥链路（【现状】，铁律级，不许绕开）

```
玩家：点目标点 / 选帆档 / 抛锚 / 调人手 / 定规矩
   ↓
航海官（Piloto）：算目标航向 vs 当前艏向 vs 风向 → 选航法（保持/转向/抢风/顺风换舷）
   ↓
水手：调帆（耗时 = f(技能, 人数, 疲劳)；精度 → 实际攻角与最优攻角的差）
   ↓
帆的实际角度 + 风场 → 气动 → 船的位置与速度
   ↓
表现（甲板 / 舱内 / 登陆 / 海图 / 面板）
```

**为什么这条链子是体验支柱**：玩家在**目标与风险**上做决策，
而不是在"按哪个键收帆"上做操作。船员疲劳 → 换舷变慢 → 在暗礁前来不及转向 → 撞上，
这是一个完全由系统自己长出来的事故。

帆态面板（`Tab`）的职责不变：**让玩家看懂"船慢"到底是风不对，还是船员没调好。**

### 6.2 船员：12 关键 + 28 普通（【现状】）

- 12 名关键船员（领航员/大副/舵手/水手长/木匠/捻缝工/桶匠/外科医生/炮长/事务长/文书/厨师）
  跑完整需求循环（需求、心情、关系、技能影响操船）。
- 28 名普通船员（水手 / 见习 / 侍童）用简化模型：岗位 + 一个工作状态。
- 数据真源 `data/defs/crew_12.json`；名册按**船 id 做种子**确定性生成。

### 6.3 十项属性（【定稿】补两项）

| 属性 | 状态 |
|---|---|
| 姓名 / 身份 / 职业 / 技能 / 性格 / 健康 / 心情 / 关系 | 【现状】 |
| **信仰** | 【定稿】影响高压抉择里的态度（口粮/处罚/异端/当地文明接触），不改操船 |
| **对船长的态度** | 【定稿】每个关键船员对船长单独一个值，由奖惩/配给/是否带他上岸累积 |

【改写】docx 第十四节列的十项全部保留，但**信仰只在"社会与抉择"层产生后果**，
不进入气动或战斗数值 —— 理由：让"不产生行为差异的属性"进模拟会同时增加
存档体积与调试成本，而它带来的差异化在抉择卡上已经够了。

### 6.4 规则制度：十条（【现状】六条 + 【定稿】四条）

| # | 规矩 | 状态 |
|---|---|---|
| 1 | 口粮制度 | 【现状】 |
| 2 | 饮水制度 | 【现状】 |
| 3 | 值班制度 | 【现状】 |
| 4 | 酒类规定 | 【现状】 |
| 5 | 宵禁 | 【现状】 |
| 6 | 处罚制度 | 【现状】 |
| 7 | **战利品分配** | 【定稿】 |
| 8 | **贸易收益分配** | 【定稿】 |
| 9 | **探险所得分配** | 【定稿】 |
| 10 | **赌博规定** | 【定稿】 |

**形状不变**：规矩永远是一张"档位 → 数值"的表（`data/defs/rules.json` + `scripts/rules.gd`），
消费它的系统只读乘数。判据也不变：**改一档，消耗/疲劳/心情/紧张度必须真的变**。

后四条要接的东西：战利品/贸易/探险收益的分配 → 金钱、船员对船长的态度、
紧张度与纪律；赌博 → 偷窃与怠工概率、关系变化。

### 6.5 船上社会（【现状】+【定稿】补齐 docx 第十六节的阶梯）

现状：关系（12 名关键船员之间 66 对）、三伙人的凝聚力、紧张度、纪律、九种递进事件、
三个高压抉择、`why_unhappy(member)` —— 面板上直接写"他为什么心情差"。

【定稿】补齐两级：

- **下层阶梯**：偷窃 / 赌博 / 酗酒 / 消极怠工（现状只有争吵与打架）。
- **上层阶梯**：派系冲突 / 违抗命令 / **逃亡** / **叛乱**。
  叛乱必须是可复现的阶梯（缺粮 → 紧张度 → 派系 → 违抗 → 叛乱），
  并且**玩家有可用的应对手段**（处罚档位、配给、带他上岸、谈判/镇压）。

【定稿】**缺粮会死人**：v0.5 缺粮只记账（士气与效率后果留给 M5，但没有死亡）。
v1.0 补上健康衰减 → 死亡，因为在三年的尺度上"不会饿死"会让中期完全失去压力。

### 6.6 验收口径

1. 改一条规矩（十条都能改）→ 至少一个可断言的数值/行为变化。
2. 信仰与"对船长的态度"进存档契约（漏一个字段 `test_save` 当场报字段名）。
3. 叛乱链：给同样的初始条件，能复现出同一条阶梯；玩家用不同手段应对得到不同结局。
4. 缺粮 → 死亡：无补给的长航程必然减员，且减员顺序可解释（先弱后强、按岗位权重）。

## 7. 船长离船与探险队

### 7.1 两种方案（【现状】方案 B；【定稿】把两种都做成"可选"）

| 方案 | 谁去 | 玩家能做什么 | 代价 |
|---|---|---|---|
| **A 派队** | 船员组成的探险队，船长留在船上 | 继续控制船、安排人手、看海况 | **无法直接控制探险队**，只能等报告/信号/传令 |
| **B 御驾亲征** | 船长本人带队 | 亲自探索、交涉、调查、做即时抉择 | **暂时失去对船的直接控制**（交给大副与既定规矩） |

**联机映射（【定稿】的重要一条）**：四个玩家各有一条船时，
**方案 A 天然成立** —— 一个人上岸，另一个人留在船上，
这正是 docx 第六节"船长在哪里"在多人下的自然形态，不需要额外机制。

### 7.2 失去联系机制（【现状】+【定稿】扩一条）

现状：延迟消息、事件摘要、返回报告（`pending_reports`）、蹭滩提示。
【定稿】补"远处信号"与"派传令的人"两种：前者是单向的、延迟的、可能看错的；
后者要占用一个人、并且路上可能出事。**都不允许实时双向指挥** —— 那是这一节的全部意义。

### 7.3 探险的产出（【定稿】按 docx 第二十四节补全）

| 产出 | 状态 | 进哪儿 |
|---|---|---|
| 遗迹 / 淡水溪流 / 村落接触 | 【现状】 | 日志、知识、当地文明态度 |
| **沉船 / 海底遗迹** | 【定稿】 | 打捞（货物 + 知识 + 世界记忆） |
| **宝藏** | 【定稿】 | 财富成果 |
| **新物种 / 新资源** | 【定稿】 | 知识八类里的"物种" |
| **未知民族** | 【定稿】 | 势力表新增一条当地文明 |

**每一样都必须进五类结算**（第 15 章），否则它只是风景。

### 7.4 验收口径

1. 方案 A 与方案 B 各有断言：A 期间船按既定规矩继续跑、探险队自主出结果；B 期间船由大副接管。
2. 联机下"一个人上岸、另一个人留在船上"能同时进行，且两边看到同一份世界。
3. 五种探险产出各自有一组断言，且都出现在结算页的对应类别里。

## 8. 外部势力与外交

### 8.1 势力清单（【定稿】docx 第二十六、二十七节）

| 势力 | 性质 | 玩家能做的 | 真源 |
|---|---|---|---|
| **西班牙王室** | 出资方与评价者 | 接受/违抗命令、上交战利品、影响结局档位 | 【定稿】`factions.json` + 王室命令表 |
| **葡萄牙** | 主要外部压力 | 逃跑 / 躲避 / 改线 / 谈判 / 伪装 / 战斗 | 【定稿】追捕线（第 9 章） |
| **当地文明** | 多个独立群体 | 贸易 / 补给 / 情报 / 文化交流 / 冲突 | 【现状】`culture.gd`（三档态度 + 态度值）→ 扩到多群体 |
| **商人** | 中性的船与人 | 买卖、交换情报、雇引水 | 【定稿】 |
| **海盗** | 风险来源 | 逃 / 打 / 交钱 | 【定稿】海战的主要来源之一 |
| **其他航海者** | 氛围与情报 | 交换情报、跟随、遭遇 | 【定稿】 |

### 8.2 态度模型（【现状】的形状，【定稿】扩到势力级）

三档态度（友善 / 中立 / 敌对）+ 一个连续的态度值；
玩家的行为改态度值，跨阈值才换档。**同一个文明内部的不同群体可以态度不同**
（docx 第二十七节明确要求）—— 落地口径是"每个群体一条独立记录"，不是"每个文明一条"。

### 8.3 世界记忆（【现状】）

`Voyage.memory` 记：贸易 / 毁约 / 打捞 / 知识 / 杀伤。
【定稿】把记忆的**读者**扩到：势力态度、王室评价、当地文明、结局档位、结算页。
判据：**玩家做过的事必须能被至少一个系统读到**，否则它是死数据。

### 8.4 王室命令（【定稿】docx 第四十一、四十二节的"执行程度"）

【定稿】给远征定一份**命令表**（3–5 条硬指标，例如"找到通往香料群岛的航路"
"带回一定量的香料""不得私自改变远征目的"）。每条命令：

- 有明确的**完成条件**（可断言）；
- 完成/违抗都进世界记忆；
- 直接决定结局档位（第 15 章）。

【改写】docx 只说"对王室命令的执行程度"，没说命令从哪来。
定稿把它做成一张**开局就摊开给玩家看**的表 —— 理由：玩家必须知道自己被怎么评判，
否则"违抗命令"就不是一个选择，而是一次意外。

### 8.5 验收口径

1. 势力态度：一次行为 → 至少一个势力的态度值变化 → 跨阈值换档 → 港口/贸易/遭遇行为变化（可断言的链）。
2. 王室命令：每条命令都有"完成"与"违抗"两条可复现路径，且都体现在结局档位里。
3. 多群体：同一个文明的 A 群敌对、B 群友善时，游戏行为分别符合各自态度。

## 9. 葡萄牙追捕线（docx 第二十九节）

### 9.1 六环状态机

```
被发现 → 被跟踪 → 被警告 → 被驱逐 → 被拦截 → 被攻击
   ↑                                              │
   └────────── 甩掉（脱离 N 天）──────────────────┘
```

| 环 | 触发 | 世界上的表现 | 玩家能做什么 |
|---|---|---|---|
| 被发现 | 在葡萄牙势力范围/航线附近被目击 | 出现一条葡萄牙船（抽象或细化） | 改线、伪装（换旗/改航向）、加速脱离 |
| 被跟踪 | 被目击后未脱离 | 那条船保持距离跟着 | 夜航/雾里甩、绕岛、硬拼 |
| 被警告 | 跟踪持续到位 | 来一条船要求你停船受检 | 谈判、交钱、拒绝 |
| 被驱逐 | 拒绝检查 | 港口态度变化、被拒绝补给 | 换港、向内陆或外海转移 |
| 被拦截 | 进入关键海域（海峡/香料群岛） | 拦截编队出现 | 谈判、战斗、投降 |
| 被攻击 | 谈判破裂或反复违抗 | 舷炮开火 | 打（第 10 章）、跑、接舷 |

**权威归属**：追捕环由**房主**推进（它是世界状态），
但"我这条船打成了什么样"由拥有者判定（第 4.4 节的第三条）。

### 9.2 与结算的关系

追捕线必须能改变结局：被拦截过、被驱逐过、与葡萄牙交手过都进世界记忆与
"历史与政治成果"，并影响王室评价（西班牙与葡萄牙在这个时代的关系是政治问题）。

### 9.3 验收口径

1. 六环每一环都有可复现的进入条件（给同样的位置/时间/旗标得到同一环）。
2. 三条应对路径（甩掉 / 谈判 / 打）各有一组断言。
3. 追捕结果进结算与结局档位。

【不做】海上逼停的"接舷登船夺船"只做为**接舷战的后果之一**（赢了可以拿物资），
不做"抢一条葡萄牙船据为己有"这一整套换船流程 —— 换船只走第 5.2 节的远征船。

## 10. 战斗

### 10.1 三种战斗（【现状】两种半）

| 形态 | 状态 |
|---|---|
| **陆战**（5–15 人独立单位的实时小队遭遇） | 【现状】`land_battle.gd`，含地形缺失、当地人战术简单等已知限制 |
| **船对岸**（船上炮位轰岸 / 岸上武装轰停泊的船） | 【现状】只做到接口与损伤链路 |
| **船对船（实时舷炮 + 接舷）** | 【定稿】v1.0 新增，`docs/23` M10 |

### 10.2 实时舷炮海战（【定稿】）

**复用陆战那一套框架**：单位化、确定性、查表、受击方权威。

| 要素 | 口径 |
|---|---|
| 单位 | **炮组**（1 个炮组 = 2–4 人 + 一门炮），不是"船有一根血条" |
| 装填 | 每门炮独立装填（分钟级），炮组人数与技能决定装填速度 |
| 射程与弹种 | 实心弹（打结构）/ 霰弹（打人）/ 链弹【定稿】可选（打帆索） |
| 命中 | 技能 × 距离 × 相对运动 × 天气查表 + 确定性偏差（不用随机数） |
| 损伤 | 落到第 5.4 节的七处损伤上，不新开一套 |
| 接舷 | 钩住 → 跳帮人数 → 在两条船的甲板上打一场"陆战"（复用同一个战斗框架） |
| 视野 | 硝烟降 `visibility_m`；并且**寻敌真的受它限制**（v0.5 的已知限制，v1.0 补上） |

### 10.3 海战的四条硬指标

与气动的四项、火器的四项同一套路：**任何一条不成立，就说明海战只是"有烟有响"**。

| # | 硬指标 | 判定方式 |
|---|---|---|
| 1 | **装填不是装饰**：每门炮两发之间的间隔不低于真源给定值（分钟级）；无头跑 10 分钟遭遇统计发数 | |
| 2 | **齐射胜单打**：同样 6 门炮，同时齐射的总伤害 ≥ 各自为战的 1.8 倍（沿用陆战的口径） | |
| 3 | **接舷决定近战**：跳帮人数与近战质量决定结果；人数劣势方靠火器不能反杀 | |
| 4 | **弹种不能互换**：霰弹对人员集中 100–200 m 内、对结构 ≤ 实心弹的 10%；实心弹对人员威胁极低 | |

数值真源：`data/defs/weapons.json`（扩到舷炮与接舷），
离线标定脚本沿用 `tools/weapons_prototype.py`。

### 10.4 联机下的战斗

沿用三条约定（【现状】陆战已写，v1.0 扩到海战）：
1. **确定性**：命中与伤害用查表 + 确定性偏差，不用随机数（无头可测、联机可复现、逐发可复盘）。
2. **开火方只广播"谁向谁开火"**；**受击方权威判命中并广播结果**。
3. **船的损伤复用既有三处链路**（船体→阻力、桅杆→帆面积、舵→转舵效率），不新开。

### 10.5 验收口径

1. 无头可复现一场舷炮遭遇（同初始条件 → 同轨迹、同伤亡）。
2. 四条硬指标全绿（`test_naval`）。
3. 双进程对打一场：两边伤亡名单与损伤一致。
4. 接舷战复用陆战框架并复用同一份伤亡/讣告链路。

## 11. 资源与经济

### 11.1 资源八项 + 火器三项（【现状】）

真源 `data/defs/resources.json`（与 `ship_physics.json` 同等地位）：
食物 / 淡水 / 弹药 / 木材 / 帆布 / 药品 / 金钱 / 货物；
火器另有三项：火药 / 铅弹 / 火绳。
载重上限来自**船的数据**（`caravel_60.json` 的 `deadweight_t`，由 `gen_ship.py` 生成）。

**小数记账**（【现状】）：消耗不足一件的先攒着（`Cargo._take`），
否则一次结算至少扣一件，水会被放大六倍。

### 11.2 跨洋贸易（【定稿】docx 第二十八节）

- 每个港口有**地区商品表**与**需求系数**（`ports.json` 的 `mul` 扩展）。
- 价格随库存压力浮动（【现状】），v1.0 再加**地区价差**：同一件货在摩鹿加便宜、
  在伊比利亚贵，玩家自己形成贸易网络。
- **知识/情报可交易**（【定稿】，v0.5 的已知限制）：海图与情报是商品，
  卖出去会进世界记忆，也可能被别人用来对付你。
- **联机两段式交易**（【定稿】，v0.5 的已知限制）：客户端"申请 → 房主执行 → 回执"，
  因为交易同时改港口库存（房主权威）与自己的货舱（本船权威）。
- **招募**（【定稿】，v0.5 的已知限制）：港口与当地可以补人；
  招募来的人进名册的简化层，技能按港口/来源分布。

### 11.3 验收口径

1. 买卖守恒：库存 + 货舱的总量在交易前后守恒（沿用 `test_ports` 的口径）。
2. 价差真的存在：同一件货在两个港的价格差能覆盖航程成本（否则跑商无意义）。
3. 知识交易：卖出后买方（AI 或世界状态）真的会用它（至少一个可断言的行为变化）。
4. 招募：招来的人有岗位、有技能、进存档、进结算（生还人数）。

## 12. 自然环境

### 12.1 十项（docx 第三十一节）

| 项 | 状态 | 效果 |
|---|---|---|
| 暴风雨 | 【现状】 | 风近两倍、每小时砸损伤 |
| 无风带 | 【现状】 | 困在原地（**已实测是"走不到终点"的主因**，见 `docs/21`） |
| 浓雾 | 【现状】 | 看不见岛（`visibility_m`） |
| 暗礁 / 浅滩 | 【现状】 | 碰撞与擦滩 |
| 强风 | 【现状】 | 帆面积压力、换帆风险 |
| 洋流 | 【现状】 | 按"相对水的速度"作用于受力，不挂帆也会被带走 |
| **飓风** | 【定稿】 | 比暴风雨更强的档位：可折桅、可迫使玩家改期 |
| **巨浪** | 【定稿】 | 甲板工作受限（不能调帆/炮击）、有落水风险 |
| **雷暴** | 【定稿】 | 短时强风 + 视野骤降 + 火绳受潮（与火器直接联动） |
| **季节与季风** | 【定稿】 | 见下 |

### 12.2 季节与季风（【定稿】，v0.5 的已知限制）

新增真源 **`data/defs/climate.json`**（与 `weather.json` 同等地位）：

- 每个纬度带在一年里有它的**季风方向窗口**（西南季风 / 东北季风）。
- 季风决定"什么时候能过这条海峡/这片海"—— 这是三年尺度上**最有意义的日历压力**。
- 飓风季给印度洋与加勒比一个**危险窗口**，玩家可以选择绕、等、或赌。

**为什么这条最重要**：没有季节，三年和三个月没有区别；
有了季节，"等一个季风窗口"才会和"绕远路"变成真实的取舍。

### 12.3 磨损与消耗的尺度（【现状】的铁律）

天气磨损一律按**航程小时**给，不按游戏小时：
`damage_per_hour × 60 游戏秒 × real_km_per_map_km / 3600`。
（踩过的坑：不乘压缩系数，一趟两天的航程掉 16% 船体，一夜把船开报废。）

### 12.4 验收口径

1. 十项天气各自有可复现的进入条件与至少一个可断言的效果。
2. 季节：同一条航线在季风窗口内外航程时间明显不同（可量化）。
3. 飓风季：给三条应对（绕/等/赌）各一组断言。

## 13. 事件与连锁

### 13.1 三池（docx 第三十四节，【现状】形状 + 【定稿】扩量）

| 池 | 【现状】 | 【定稿】v1.0 |
|---|---|---|
| 外部 | 风暴 / 敌舰 / 土著接触 / 新岛屿 / 沉船 / 宝藏 / 新航线 / 其他船只 | 每类补到全球区域专属事件（印度洋、太平洋、大西洋各自的池子） |
| 船内 | 船员冲突 / 疾病 / 偷窃 / 饥饿 / 失踪 / 叛乱 / 火灾 / 纪律 | 全部补齐（现状只有冲突、疾病、饥荒相关的几条） |
| 探险 | 与当地人交流 / 遗迹 / 宝藏 / 野生动物 / 陌生疾病 / 陷阱 / 当地冲突 | 全部补齐 |

真源：`data/defs/events/*.json`（现状四个文件：`chain` / `expedition` / `external` / `ship`）。

### 13.2 连锁（docx 第三十五节，【现状】六环）

现状有一条六环因果链：**与当地人打起来 → 部落敌对 → 港口拒卖 → 被迫闯风暴带 → 船只损伤 → 士气下降**。
【定稿】的要求不是"再加几条链"，而是**每一条链都能看见**：
每一步都在日志里留一行、在世界记忆里留一个旗标，玩家事后能复盘"这串事是怎么连起来的"。

### 13.3 事件与铁律的边界（【定稿】明确一条）

docx 说"事件可以打断航行"。落地口径：

**事件可以给玩家"必须回应的抉择"，但不能直接改船的位置或速度**（铁律 1）。
事件只能改状态（旗标、态度、记忆、资源、损伤）与给指令，
船的移动永远是气动的结果。例：链里的"被迫闯进风暴带"不是把船瞬移过去，
而是"当前的风与洋流会把你推进风暴带"，或者"玩家在抉择卡里选了继续前进"。

### 13.4 验收口径

1. 每条因果链：逐环断言，且中途改一个选择能得到不同的后续（沿用 M5/M7 的口径）。
2. 三个池各自的触发次数/冷却有断言，保证"不会永远不出现"（踩过的坑：冷却比状态寿命还长）。
3. 事件不越权：`check_motion_ownership` 继续全绿。

## 14. 知识 · 航行日志 · 航线

### 14.1 知识（docx 第三十七节，【现状】）

知识不是科技树，是**玩家对世界的认知程度**：未知海域 → 第一次穿越 → 发现稳定洋流 →
确定最佳航行时间 → 形成可靠航线。真源 `scripts/knowledge.gd`，八类条目，
`K` 键摊开的知识与日志面板。

【定稿】补两条：
1. **知识可交易**（第 11.2 节）—— 它必须能换来钱或者别的东西。
2. **知识影响可选项**：认得某条洋流/季风之后，面板与航线上多出"推荐窗口"这类提示。
   （判据：知识要能改变玩家能做的决定，否则它只是收集品。）

### 14.2 航行日志（docx 第三十六节，【现状】）

文书（Escribano）记录：到过哪儿、做过什么决定、船伤成什么样、里程碑日期。
**它是结算页的唯一数据源**（`scripts/journal.gd` → `scripts/settlement.gd`）。
它同时也是"玩家故事"的载体：最终给玩家的不是一条固定剧情，
而是"**这是我这一次环球航行发生的事情**"。

### 14.3 航线（docx 第三十八节）

- 每段航线有元数据：距离 / 时间 / 风险 / 补给机会 / 商贸价值 / 战略价值。
- 【定稿】海图上可以**插旗与记航线**（v0.5 的已知限制：拉远之后左键仍然只是"设目标点"）。
- 航线是**辅助**不是方向盘：玩家随时可以左键自己点目标点退出跟随。

### 14.4 验收口径

1. 知识的每一类都能被"发现 → 记录 → 在结算里计分"。
2. 海图插旗与记航线进存档，读回来还在。
3. 航段元数据是**推出来的**，不另写一份表（玩家看到的与真会遇到的是同一份数据）。

## 15. 结算与结局

### 15.1 五类成果（docx 第四十一节，【现状】的算法，【定稿】扩到全球）

| 类别 | 【现状】的数据来源 | 【定稿】补什么 |
|---|---|---|
| 财富 | 金币 + 货折价 + 贸易/打捞次数 + 抉择分 | 跨洋贸易网、宝藏、战利品 |
| 航海 | 里程、抢风段数、已发现分块、到过的港 | 麦哲伦海峡/太平洋/好望角这些**关键地理成就** |
| 知识 | 八类条目数 + 抉择分 | 可交易知识、物种与地理资料 |
| 船员 | 生还 − 阵亡×12 − 带伤×3 + 心情 + 纪律 + 抉择分 | 三年尺度：更替、招募、叛乱与逃亡 |
| 历史与政治 | 抉择分 − 毁约×6 − 杀伤×5 + 势力态度 + 结局旗标 | 王室命令执行度、葡萄牙关系、外交危机 |

**"全队抵达"仍然是最高档的前提**（v0.5 定的：4 艘船都到才给"巨大荣誉"）。

### 15.2 四档结局（docx 第四十二节，【现状】三档 → 【定稿】四档）

| 档 | 进入条件（口径） |
|---|---|
| **巨大荣誉** | 完成环球 + 全队抵达 + 总分 ≥ 高档阈值 + 王室命令基本完成 |
| **普通成功** | 完成环球 + 总分 ≥ 中档阈值 |
| **失败式归来** | 完成环球，但财富不足 / 船队损失严重 / 知识成果低 |
| **政治惩罚** | 完成环球，但严重违抗命令 / 造成重大损失 / 与重要势力外交危机 / 私自改变远征目的 —— 极端情况入狱 |

**核心命题（docx 原话）**："完成环球航行"和"完成一次成功的环球远征"是两个不同的概念。
所以**每一档都必须有确定的进入条件与可复现的路径**，
并且"完成但被惩罚"这条线必须真的能走到（不能只写在文案里）。

### 15.3 验收口径

1. 四档结局各有断言（`test_settlement` 扩写），且四档互斥、覆盖所有情况。
2. 王室命令：完成与违抗都能改档。
3. 结算页在**正常游戏**里会自己弹出来（v0.5 收尾才接上，这条不许回退）。
4. 联机：结局旗标铺到每个客户端（沿用 `test_net_loopback` 的口径）。
