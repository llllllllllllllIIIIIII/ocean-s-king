# 港口 · 资源 · 贸易（v0.5 · M4）

> 这一期的目标是让**"能不能走到巴西"变成一个真的需要盘算的问题**：
> 带多少水、留多少仓、在哪个港卖什么。对应 `docs/13-v0.5开发计划.md` 的 M4 卡片；
> 权威归属见 `docs/14`，世界与压缩系数见 `docs/15`，联机见 `docs/16`。

---

## 1. 先说一件必须先定下来的事：时间尺度

M2 定的是"空间压缩、时间诚实"：船按真实速度在 48km 的压缩地图上走。
可这样一来"一天吃多少"就没法算了 —— 圣卢卡尔到加那利只要 1.7 个游戏小时。

所以 M4 把**压缩系数**写进了世界数据（`data/world/atlantic/geography.json`）：

```
real_km_per_map_km = 6000 ÷ 48 = 125
```

于是同一件事有两个尺度，各管各的：

| 尺度 | 用在哪 | 例子 |
|---|---|---|
| **地图尺度** | 船的速度、位置、两个港之间的距离 | 圣卢卡尔→加那利 = 8.5 地图公里、1.7 个游戏小时 |
| **真实航程尺度** | 日历、口粮与淡水的消耗、价格与修船的"日子感" | 同一段航程 = 1059 真实公里 = **4.8 个航程日** |

推论（换了一个显示口径，值得单独说）：**HUD 上的时钟走得比现实快 125 倍** ——
一个游戏小时 = 5.2 个航程日。看着像快放，但那是"一段横渡要走三周"的正确表现；
结算页上的日期也是这么翻的（`VoyageJournal.voyage_time_scale`）。

> 迷你海域（`test_sea.json`）没有这个字段，默认 1.0，
> 所以 v0.1 那批测试的日期断言原样成立。

## 2. 资源与载重

真源是 **`data/defs/resources.json`**（和 `ship_physics.json`、`weapons.json` 同等地位）：
一个单位多重、一天吃多少、修满船体要几捆木头，全在那儿。

| 类别 | 东西 |
|---|---|
| 消耗 | 食物（1 份 = 1.5kg）、淡水（1 桶 = 60L）、药品 |
| 修理 | 木材、帆布 |
| 弹药 | 火药、铅弹、火绳（M6 会真的消耗它们） |
| 货物 | 象牙、巴西红木、欧洲呢绒、葡萄酒、盐 |

**载重来自船的数据**：`data/ships/caravel_60.json` 的 `deadweight_t: 27`（由
`tools/gen_ship.py` 生成）。装不下就**一件都不装**（`Cargo.add` 返回 false），
不会悄悄丢一半 —— 这条有断言。

出发时船上有 120 份食物、8 桶水、4 捆木头…… 都不够开到加那利：
**这就是"必须补给"的意思**。

## 3. 消耗：按航程日、按小数记账

```
一天：1 份食物 / 人，3 升水 / 人（四十个人 = 40 份 + 2 桶）
结算：每 60 个游戏秒一次 = 0.5 个航程小时（×125）
```

这里踩过一个坑，值得写下来：**按"整件"结算会把水放大六倍**。
四十个人一分钟只喝十升，而一桶是六十升 —— 每轮都"进一位"的话，
一个上午就能把一船水喝光。所以 `Cargo._take()` 是**小数记账**：
不足一个单位的先攒着，攒够一件才真扣，缺的继续攒着（所以连着缺几轮的账也对得上）。

缺粮缺水**只记账**：`cargo.starving` / `shortage_events` / `Cargo.shortage_total`。
士气与效率的后果是 M5 的规则与事件的事 —— 这一期不越界。

## 4. 港口经济

`data/world/atlantic/ports.json`：每个港的**服务**、**库存**、**地区系数**。

```
价格 = 基准价 × 地区系数 × 库存压力
库存压力 = clamp(2 − 现有库存 / 基准库存, 0.5, 2)
卖价 = 买价 × 0.9（港口的利差）
```

买光了就贵一倍、堆满了就便宜一半 —— **买卖真的会推着价格走**，
所以"低买高卖"是要挑时候的：

| 货 | 在非洲（圣地亚哥） | 在欧洲（圣卢卡尔） |
|---|---|---|
| 象牙 | 便宜 | 贵 |
| 欧洲呢绒 | 贵 | 便宜 |
| 巴西红木 | 中等 | 贵 |

**守恒**：所有买卖都从 `Ports` 这一个口子进出，所以"港口 + 船上的总件数"
是一个可以随时断言的量 —— 买不造货、卖不吞货，测试里两种操作各断言一次。

**权威**：库存与价格是 `WorldState`（房主权威，`docs/14` 第 2 节）。
推论见下面的限制清单。

## 5. 修船

在港口花**料 + 工钱**修：修满 100% 船体要 12 捆木头、6 匹帆布、200 金币；
修一半就是一半。`check_motion_ownership` 管的是"谁写速度与位置"，
修船走的是 `ship.apply_damage(part, -x)` 这个**指令入口**（和木匠那件事同一个口子）。

验收第 2 条（"船体损伤不修，到巴西时航速明显掉"）用的是 v0.1 就有的那条链：
船体损伤 → 阻力变大 → 同样的风跑得更慢。测试里两条一模一样的船，
一条 60% 损伤，跑同样的 900 秒：慢 15% 以上才算过。

```powershell
& $g --headless --path . --script res://tests/test_resources.gd   # 41 项
& $g --headless --path . --script res://tests/test_ports.gd       # 54 项
```

验收标准 → 证据：

| 验收 | 证据 |
|---|---|
| 1. 装到"刚好开到加那利"的补给量；不做补给，中途缺水缺食 | `test_resources`：这一程 4.8 个航程日、要 191 份食物 + 10 桶水；出发时的存货不够；装够了一路不缺（到了只剩 42 份）、只装一半第 1 次结算就缺 |

| 4. 没有火药铅弹就打不了仗 | `test_resources`：`cargo.can_shoot()` 的三条前置（火药 / 铅弹 / 火绳）各断言一次，M6 接这个口子 |

## 8. 已知限制

| 限制 | 说明 | 什么时候 |
|---|---|---|
| **联机时只有房主能买卖** | 交易会同时改"港口库存"（房主权威）和"自己的货舱"（本船权威）。客户端做两段式确认（申请 → 房主执行 → 回执）要一套新的消息与回执状态，这一期不做。客户端在港口里能看到价格与库存（只读），但按不下"买" | v0.6+ |
| 没有招募 | M4 卡片的砍单预案允许（"招募改固定名单"），而且它不在验收里 | v0.6+ |
| 港口不分昼夜、不看潮汐 | 1519 年真实的港口要等潮水；切片不做 | 不做 |
| 价格不随时间波动 | 只有"库存压力"这一层；没有季节、没有战争溢价 | M7 |
| 船员不会因为缺粮而死 | 缺粮只记账，后果（士气/效率/疾病）是 M5 | M5 |

## 9. 这一期踩到的坑

| 坑 | 症状 | 对策 |
|---|---|---|
| 按"整件"结算消耗 | 一次结算至少扣一件 → 水被放大六倍，一上午喝光一船水 | `Cargo._take()` 小数记账：不足一件的先攒着 |
| 测试里的"到港就跳出" | 出发港本身就在港圈里，循环第一次迭代就 break，于是什么都没消耗 | 判"到的是不是**下一个**港"（按距离，而不是 is_port） |
| 港口库存键与字段覆盖断言 | `capture_state()` 直接返回 `{港口id: {...}}`，测试找不到 `stock` 这个字段 | 包一层：`{"stock": {...}}` —— 键名 = 变量名（`docs/14` 的老规矩） |
| 载重上限在代码里写死 27 吨 | 换一条船就错 | 从 `caravel_60.json` 的 `deadweight_t` 读（生成器写进去的） |
