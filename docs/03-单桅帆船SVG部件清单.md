# 单桅帆船 · SVG 部件清单（待你核实）

> 你要求"船比较精细，需要画一些部件的 SVG，最后拼接成一个矢量图"。
> 这份文档把"要画哪些部件、怎么拼、怎么保证对得齐"写死，
> 好在 Day 2 之前就能让你确认，避免画完再返工。

---

## 1. 为什么是 SVG（而不是位图）

| 好处 | 对游戏的具体意义 |
|---|---|
| 无损缩放 | 正交摄像机要能从"整片海"拉到"甲板上一颗钉子"，位图会糊，矢量不会 |
| 部件可替换 | **换一个破损版的帆 = 换一个文件**，损伤可视化几乎免费 |
| 可程序化变换 | 帆的收放角、帆桁的旋转直接改 `transform`，不需要画多套 |
| 文本格式 | git 能看 diff，能版本管理，能和 `ship.json` 一起走 GitHub |
| 体积小 | 几百个部件加起来还是几百 KB |

**不使用 AI 生成位图**：这是矢量代码资产，手绘 SVG 更可控、更可复用。

## 2. 坐标与锚点规范（这是"能不能对得齐"的关键）

### 两类部件，两套定位方式

**类型 A：固定部件**（船体、甲板、舷墙）——共用同一套世界坐标

- 所有固定部件用**同一个 viewBox**，原点在**桅杆底座**，1 米 = 100 单位
- 例：一艘 15 米长的船 → viewBox 覆盖 x ∈ [-500, 300]、y ∈ [-750, 750]
- **好处**：这些部件直接叠放就对齐，`ship.json` 里不需要写坐标

**类型 B：可动部件**（帆、帆桁、舵、绞盘）——局部锚点 + 变换

- 每个部件自带局部原点（通常是转轴），`ship.json` 指定位置与角度
- `transform` 由运行时计算：帆的角度 = 玩家的收放命令 + 风向导致的偏移

### 拼接层序（从下到上，z-index 固定）

```
00 船体俯视轮廓      hull_outline
01 船壳板缝          hull_planking
02 甲板铺板          deck_planks
03 舷墙 / 栏杆        bulwark / rail
04 舱口 / 格栅        hatch / grating
05 甲板设施（固定）    capstan / windlass / gun / boat
06 索具（下层）        shrouds / stays
07 桅杆               mast
08 帆桁 / 下桁         yard / boom
09 帆                  sails
10 索具（上层）        sheets / lines
11 上层标注 / 交互高亮  overlay
```

### 命名规范

```
{类别}_{部件}_{状态}.svg

例：
  sail_main_normal.svg     主帆 · 正常
  sail_main_reefed.svg     主帆 · 缩帆
  sail_main_torn.svg       主帆 · 破损
  hull_outline.svg         船体轮廓（无状态变体）
```

## 5. 尺寸基准（已定）与还需确认的两件事

### 已定：尺寸基准

**规格 B：约 60 吨 / 20 米，单桅拉丁帆。**

- `hull_outline.svg` 按 **20 米**船体绘制：艏艉更修长，艉楼更高，比 15 米的小船明显"体量感"更强。
- 1 米 = 100 单位 → 俯视 viewBox 约 x ∈ [-700, 400]、y ∈ [-1000, 1000]。
- **拉丁帆（lateen）**：挂在下桁（boom）上的三角帆，不是方帆。
  这对 SVG 影响很大——`sail_main_normal.svg` 是**三角形**，而且下桁很长、倾角明显，
  是这艘船最有辨识度的外形特征。

### 还需你确认的两件事

1. **俯视轮廓风格**：你要**纯几何**（直线 + 圆弧，干净但偏示意），
   还是**手绘感**（略带不规则线条，像古海图）？后者更贴题材，但每个部件要多花时间。
2. **舷侧的处理**：纯俯视看不到船壳侧面。要不要给船体轮廓加一圈"伪立体"的厚度阴影
   （看起来像有一点高度感），还是保持完全扁平？
