## 1. 天气不是动画

`data/defs/weather.json` + `scripts/weather.gd`。五种天气，每一种都**真的改数**：

| 天气 | 风 | 每小时损伤（船体/桅杆/舵） | 瞭望 | 疲劳 / 心情 | 火器 |
|---|---|---|---|---|---|
| 晴 | ×1.0 | — | 8000 米 | ×1.0 / +0.02 | 干燥（哑火 3.5%） |
| 雷暴 | ×1.35 | 0.15% / 0.3% | 900 米 | ×1.5 / −0.05 | 大雨（31.5%） |
| **风暴** | **×1.9** | **0.6% / 0.9% / 0.3%** | 300 米 | ×2.0 / −0.14 | 大雨 |
| 浓雾 | ×0.7 | — | **150 米** | ×1.15 / −0.05 | 潮湿 |
| 无风带 | **×0.22** | — | 8000 米 | ×1.25 / −0.08 | 潮湿 |

它接进的是**已有的四条链路**（没有新开一套）：

```
天气 → 风乘数 → 帆的受力 → 航速与到达时间（验收第 3 条的一半）
     → 每小时往船体/桅杆/舵上砸损伤（另一半）
     → 瞭望距离 → 发现陆地/分块的速度
     → 疲劳与心情乘数（M5 的名册）→ 抱怨、紧张度、事件
     → 哑火天气（M6 的战场）—— 大雨就是 31.5%
```

**按纬度带出天气**：比斯开湾以北多雾多风暴、信风带晴朗、赤道是无风带、热带海岸多雷暴。
换天气用 `(第几段, 海区带)` 的哈希决定 —— **不用随机数**，所以同一趟航程必然遇到同样的天气。

## 2. 事件池与那条因果链

`data/defs/events/` 四个文件：`chain / external / ship / expedition`，共 18 条。
每一条的 `requires` 都盯着**别的系统里的真实状态**（culture 的态度、港口的服务、
货舱的余量、天气、社会的紧张度），触发用哈希取候选 —— 同样无随机数。

**六环因果链**（验收第 1 条要的"4 环"，这里给了 6 环，每一环都靠真实状态咬合）：

```
① 部落冲突（玩家开火/抓人 → culture 敌对）
② locals_anger   当地人敌意      requires: culture green_cape == hostile
③ port_refused   港口拒绝贸易    requires: flag locals_hostile
                                 → 之后 can_trade_here() 直接返回 false（真的买不到东西）
④ supplies_run_out 补给断了      requires: flag ports_refuse + 水 < 4 桶
⑤ storm_belt     闯进风暴带      requires: flag supplies_gone → 天气被强按成 48 小时的风暴
⑥ storm_damage   风暴损伤        requires: flag storm_hit + 天气是风暴 → 船体/桅杆挨损伤
⑦ crew_despair   船员绝望        requires: flag storm_damaged + 紧张度 ≥ 0.45 → 士气与纪律掉
```

测试里这六环按顺序触发两遍，**两遍的顺序完全一样**（可复现）。

## 3. 知识：发现即记录

`scripts/knowledge.gd`：八类条目（海图 / 陆地与港口 / 风向洋流 / 物种 / 文化 /
语言 / 贸易情报 / 战争情报）。记的是 **id**，同一件事不会记两遍 ——
所以"跨洋航程结束后知识页被填满"这件事可以被断言。

现在自动记的有：认出的陆地、到过的港、上岸看到的遗迹/村落/溪流、第一次遇到的每种天气、
以及**事件带来的情报**（"这里有一片海图上没有的浅滩"）。

`K` 键摊开的就是这一页（左图右字：条目按类别分组，底下写着"世界记住了什么"与天气）。

**世界记忆**（`Voyage.memory`）是另一本账：`traded` / `broken_faith` / `salvage` /
`knowledge` / `killed`…… 它现在有两个用处：事件池的 `requires.memory_min`
和因果链里那一环（毁约 → 港口拒绝）。M8 的"历史与政治"成果会读它。

## 4. 怎么验证

```powershell
& $g --headless --path . --script res://tests/test_events.gd   # 44 项
```

| 验收 | 证据 |
|---|---|
| 1. 至少 1 条 4 环因果链可复现 | 六环按顺序串起来（`locals_anger → port_refused → supplies_run_out → storm_belt → storm_damage → crew_despair`），第二遍同样的输入得到**同样的顺序**；链子走到底留下 `despair`，船体被风暴砸出损伤 |
| 2. 跨洋之后知识页被填满 | 走四个港 + 上岸看三处 + 跑一段天气事件 → 知识从 2 条涨到 **14 条**（海图 6 / 文化 1 / 语言 2 / 贸易情报 5），分四类 |
| 3. 风暴真的改变航行结果 | 同样的起点与目标跑 1800 秒：风暴里走 **7498 米**、晴天走 **5236 米**（风乘数 1.9 的功劳），而船体损伤 **37.5% vs 0%**（每小时损伤的功劳）—— 两条都不同 |

画面证据：`.shots/47_knowledge.png`（知识与日志页）、`.shots/48_storm.png`（风暴的画面）。

## 5. 已知限制

| 限制 | 说明 | 什么时候 |
|---|---|---|
| 天气不看季节 | 只有"纬度带 + 时间"这一层；1519 年的季风/飓风季没做 | v0.6+ |
| 事件不能打断航行 | 事件是消息与数值，不会强制改变航线（除了因果链里那条"闯进风暴带"的旗标） | v0.6+ |
| 没有"其他船"的事件 | 卡片里的"其他船只/海盗"只做了"帆影"这一类氛围事件 | v0.6+（海战） |
| 知识不可交易 | 真实航海里海图与情报是能卖的；v0.5 只做了"记下来" | v0.6+ |
| 航线元数据只落了一半 | `routes.json` 有计划标风险/补给/价值，这一期先保证"航段不穿干地"与"发现才画线" | **M8 收尾已补齐** —— 见下面第 5.1 节 |

### 5.1 航线元数据（M8 收尾补齐的那一半）

| 元数据 | 从哪儿来 | 玩家在哪儿看见 |
|---|---|---|
| **补给**：图上公里 / 真实公里 / 航程日 / 口粮 / 淡水 | `Voyage.supply_need_for()`（M4 就有） | 港口面板右上角（早就有）+ 底部那一条 |
| **风险**：这一段穿过哪些天气带、哪几带要小心 | `Weather.bands_on()` / `risky_bands_on()` —— 直接读 `weather.json` 的 `bands` | 港口面板底部"路上穿过：…"；海图上标在航段中点（屏幕长度 > 200px 才标，免得挤在港口名上） |
| **价值**：终点港什么好卖、什么好买 | `Ports.best_trades()` —— 直接读 `ports.json` 的 `mul`（地区系数） | 港口面板底部"到 X：好卖 …；好买 …" |

三样都是**推出来的**，不另写一份表：玩家看到的与真的会遇上的必须是同一份数据。
**踩过的坑**：风险一开始只看航段的端点 —— 而"渡海去巴西"这一段的两端分别在信风带与
热带海岸，中间那条**赤道无风带**整个被漏掉（它恰恰是最该告诉玩家的那一条）。
现在改成沿线段每 500 米采样（`test_ports` 里有一条断言专门盯它）。

## 6. 这一期踩到的坑

| 坑 | 症状 | 对策 |
|---|---|---|
| 天气磨损的尺度算错十倍 | 一趟两个航程日的航程掉 16% 船体 —— 一夜之间把船开报废 | `damage_per_hour` 按**航程小时**给，并且用 `60 游戏秒 × 125 / 3600` 换算；风暴 0.6%/小时（一场 48 小时的风暴 ≈ 29%） |
| 用 60 秒一步跑船的物理 | 位置变成 `-nan`（积分跑飞了） | 天气/事件可以用粗步长，**船的物理必须用 `SIM_DT`**：测试里分开跑 |
| 事件冷却比天气寿命还长 | 链子第 5 环永远等不到"天气是风暴"（风暴 12 小时 = 345 游戏秒 < 900 秒冷却） | 链子里那场风暴改成 48 小时（也更像"风暴带"） |
| 老断言"航线不用蹭滩 = 0% 损伤" | M7 起天气与事件也会造成损伤，断言变红 | 断言改成"低于一次蹭滩（6%）"，并在那一段把天气按成晴天 |
